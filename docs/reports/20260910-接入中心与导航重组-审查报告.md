## 三、审查过程中**发现并修复**的真实缺陷

### D1（HIGH，已修复）：菜单整块不渲染

| 项 | 内容 |
|---|---|
| 现象 | 浏览器实测发现 `<ul class="el-menu">` 内部 **0 个子节点**，侧边栏空白 |
| 根因 | `MenuTree.nodeChildren()` 漏合并 `node.children`，只处理了 `altChildren`。导致每个分组被判定"无子节点"，又因不是叶子项（无 `path`）被 `v-if` 全部过滤 |
| 为何单测没发现 | `menu.spec.js` 只断言**配置数据**（`MENU_GROUPS` 结构），10 个用例全绿 —— **数据层测试无法替代渲染层测试** |
| 修复 | `nodeChildren()` 合并三类来源：`node.children` / `node.altChildren` / 自身降级 |
| 防复发 | 新增 `src/components/__tests__/MenuTree.spec.js`（6 用例，**真实挂载断言 DOM**），首条用例即为"至少渲染出菜单项" |

### D2（MEDIUM，已修复）：测试隔离假绿

| 项 | 内容 |
|---|---|
| 现象 | `test_integration_profiles.py` / `test_shared_doc_login.py` 首跑通过、**再跑失败** |
| 根因 | `conftest` 的 `db` fixture 靠 `session.rollback()` 做隔离，但服务层内部 `db.commit()` **绕过外层事务真正落库** → 固定 code/doc_url 在第二次运行时撞唯一校验 |
| 影响 | 属测试基建问题，但会造成 CI 偶发失败与"本地绿、CI 红"的困惑 |
| 修复 | 用例改用唯一标识（`uuid` 后缀）+ 显式自洁（`db.delete`）；`test_seed_does_not_overwrite_user_edit` 改为不动种子行（避免污染共享状态）；`test_reset_restores_seed_content` 基准改取 seed 常量而非"改前值" |
| 验证 | 连跑两次均 22 passed / 24 passed |

## 四、MEDIUM（已知约束，非本次引入）

### M1：单 worker 假设为登录会话的前提

`SharedDocLoginManager` 是**进程内单例**，会话存内存。当前部署为 Gunicorn 单 worker
（与项目既有互斥锁设计一致），故成立。**若未来改多 worker，登录会话会落到不同进程
导致"扫码后查不到会话"** —— 届时需改 Redis 存储。

> 缓解措施已在代码注释与架构文档 §五.1 显式标注，属"已知边界"而非隐藏陷阱。

### M2：登录态有效性依赖平台页面结构

`verify_logged_in` 的判定信号是"是否离开登录域名 + cookie 存在"，不依赖具体 DOM 选择器
（已刻意避开易变的选择器）。但若腾讯/金山**改版登录域名为子域**或变更 cookie 命名，
判定可能失效。

> 缓解：`confirm` 端点提供**用户手工兜底**（用户看得见页面，以用户判断为准）；且
> `_LOGIN_HINTS` / `_SESSION_COOKIE_HINTS` 集中在文件顶部常量，改版时单点可调。
