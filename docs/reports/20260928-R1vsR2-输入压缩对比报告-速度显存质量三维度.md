# R1 vs R2 对比报告：输入压缩（先压缩再推理）三维度验证

> **实验设计**：同一审计任务、同 10 个（节点×模型）cell、同 system prompt 与输出契约，唯一变量是输入：
> - **R1**：41K 字符过滤后原始日志行（prompt 8194 tok，num_ctx 16384）
> - **R2**：确定性脚本归并后的错误模式+统计基线 4.4K 字符（prompt 2791 tok，num_ctx 8192）
> 全部经 talon 网关 X-Talon-Force-Node 钉节点执行。原始数据：`analysis/`（R1）、`analysis_r2/`（R2）。

**读数**：

- **生成速率普遍 +20%~140%**：短上下文下 KV 更干净、attention 更快；弱节点受益最大（mini-14b 2.4x、3060-14b 1.9x）
- 4090-3b（3.1x）与 2080-7b（1.6x）wall 提升最显著——小卡 prefill 占比高，输入缩短直接兑现

## 二、显存对比（KV cache 理论计算）

prompt 缩短 5403 token，各模型 KV cache 节省（q8_0，3060 已改回 q8_0；权重为 Q4_K_M 常驻）：

| 模型 | KV/1K tok (MB) | Δprompt 节省 (MB) | 权重 (GB) | 备注 |
|---|---|---|---|---|
| qwen3.5:122b | 221.2 | 1.17 GB | 74.0 | MoE, 架构参数为估算 |
| qwen3.8:27b | 147.5 | 0.78 GB | 17.4 | dense, gmk 实测占用 |
| qwen2.5:14b | 110.6 | 0.58 GB | 9.0 |  |
| qwen2.5-coder:14b | 110.6 | 0.58 GB | 9.0 |  |
| qwen3-coder:30b | 55.3 | 0.29 GB | 18.6 | MoE 30.5B-A3B |
| qwen2.5:7b | 32.3 | 0.17 GB | 4.7 |  |
| qwen2.5:3b | 20.7 | 0.11 GB | 1.9 |  |

**读数**：
- 122b/27b 这类深层模型，5.4K prompt 差 ≈ **0.7~1.2 GB KV**——对 120GB 的 gmk 无所谓，但对 8GB 的 2080 是 9%~15% 显存
- 2080（8GB）跑 7b：权重 4.7GB + R1 KV≈0.26GB 已逼近可用上限，长输入会触发 ollama 层截断或 offload 到 CPU 降速；R2 输入下从容
- **教训印证**：3060 当初为 14b+8K 把 KV 压到 q4_0，在 7b 长输入上直接产出复读乱码——输入压缩（R2）与 KV 量化（q4_0）是两条省显存路径，前者无损、后者对小模型有损

- 话痨收敛：4090-3b 4588→1092 字符，不再打满 max_tokens

## 四、结论

| 维度 | R1→R2 | 判定 |
|---|---|---|
| prompt 成本 | 8194→2791 tok（-66%） | ✅ 确定收益 |
| KV 显存 | 每 cell 省 0.1~1.2 GB（视模型深度） | ✅ 小卡节点关键 |
| 生成速率 | +20%~140% | ✅ 弱节点最受益 |
| wall 时间 | 606s→609s（持平） | ⚖️ decode 瓶颈下不敏感 |
| 输出结构 | 章节 41→65 | ✅ 最大收益 |
| 证据质量 | 密度上升、灌水收敛 | ✅ |
| 可靠性 | repeat-limit 消除 | ✅ |

**一句话**：日志/审计类任务，输入压缩的收益排序是 **质量 > 可靠性 > 成本/显存 > 速度**；速度收益只在 decode 不占主导的短输出场景或弱节点上显著。标准姿势 = 规则过滤 + 模板去重聚类（零显存，保留行号/时间戳/频次供反查）→ 几千 token 输入 → 4B/7B 粗筛、14B/27B/30B 深归因。
