## 三、★关键障碍：用户要求的"姓名"键**不可用**

用户要求去重键含"姓名"，但实测：

| 表 | 字段 | 实际语义 | 可用性 |
|---|---|---|---|
| 工单 | `registrant` | **内部人员**（`wechat` 26755 / `深圳市云客猫科技有限公司` / `企微-洪佳`） | ❌ 非客户 |
| 工单 | `handler` | **处理人**（`企微-董梦玲` / `企微-吴晓龙`…） | ❌ 非客户 |
| 工单 | `contact_person` | — | ❌ **100% 为空** |
| 工单 | `submit_params` JSON | 含 `username: 兰鑫雨`（客户名） | ⚠️ **填充率仅 1.2%（389/32,058）** |
| 315 | `complainant` | 客户姓名（填充 96%） | ✅ |
| 卡商 | `complainant` | 客户姓名（填充 86%） | ✅ |

**结论**：**工单侧没有可用的客户姓名字段** →
"三者（SN+手机+姓名）都命中"实测 **0 匹配**（315）/ **0 匹配**（卡商）。

### 已验证的替代方案

| SN 或 手机（任一） | 809 | 126 | 最宽松 |

### 另一个发现：`complaintNo` 可精确匹配但量太小

工单 `submit_params` 中含 `complaintNo: 082607181428446545101`（**正是 315 的 `complaint_no`**），

## 四、我的建议

### 4.1 去重键（修正用户要求）

**推荐：`SN + 手机`（都命中）**，而非"三者"

- 理由：工单侧无客户姓名字段，"三者"会导致 **0 去重**（完全失效）
- 覆盖率：315 命中 660（**24.9%**）、卡商 85（**9.7%**）
- 若要更高覆盖，可用"任一命中"（809 / 126）

> ⚠️ 如果你坚持含姓名，**需要先在工单侧补齐客户姓名字段**（BMS 侧或工单导入时采集）
> —— 这是独立的工作项，不在本次范围。

### 4.2 分类（四桶 + 卡商独立）

```
内部投诉    工单: category 空白 AND item ∈ {商品投诉, 服务投诉}
商户号投诉  工单: category 空白 AND item = 微信投诉
外部投诉    工单: category 空白 AND item ∈ {工信部,12315,公共服务平台,消费者协会}
            + 315 补充表（按 SN+手机+30天窗 去重后）
(外)卡商    card_complaints 独立成桶
其他        空 item(81) + 套餐扣费申诉(14)
```

### 4.3 状态合并口径

因 80% 无处理日期，建议：
```
合并状态 = 任一为完成态 ? 已处理 : 未处理
展示时并列标注来源（工单状态 / 渠道登记状态）
```

### 4.4 被投诉主体

| 来源 | 字段 | 可用性 |

| 315 | `company_entity`（云客猫 1069 / 赤霄 / 小皮丘） | ✅ 50.8% |
