### C-1 🔥 CRITICAL 杉猫（BMS）平台真实账号密码硬编码并已入库、进生产镜像（TST-01/02）
- **位置**：`backend/scripts/run_shanmao_refund_debug.py:57,59`；`backend/scripts/sniff_shanmao_export_request.py:102-103`；`backend/.dockerignore`（未排除 scripts/）；`backend/Dockerfile:44`（COPY . /app）
- **证据**（主代理亲自读码）：
  - `base_cfg["username"] = os.environ.get("SHANMAO_USER", "<真实账号>")`
  - `base_cfg["password"] = os.environ.get("SHANMAO_PASS", "<真实密码>")`
  - 两文件均被 git 跟踪（存在于 HEAD 2870be2）；由提交 `8ce946b`（2026-08-05）引入，**已在仓库存在 15 天**；gitleaks 全历史扫描未检出（规则不匹配该形态）；
  - `backend/.dockerignore` 未排除 `scripts/` → 38 个调试/嗅探脚本（含此明文凭证）随 `COPY . /app` 全部进入生产镜像；`sniff_shanmao_export_request.py` 还会把含 Authorization 的完整请求头/体落盘。
- **影响**：外部平台真实账号密码在仓库与镜像内对所有人可见；**与 2026-08-17 处置过的 SCRM 凭证泄露事件（ed3ddcc）同类型，说明同类问题复发**；凭证处置手册（docs/security/credential-incident-remediation.md:116）要求重扫 scripts/ 但未落实。
- **建议**：
  1. 立即在杉猫平台侧轮换该账号密码（最高优先，先于代码清理）；
  2. 删除两处硬编码默认值，改为从 .env/DB 强制读取并 fail-fast；
  3. `backend/.dockerignore` 增加 `scripts/`、`tests/`；重建镜像验证 `/app/scripts` 不存在；
  4. gitleaks 增加覆盖 `SHANMAO_PASS` 等变量名与"逗号后默认值"形态的规则，全仓 `gitleaks detect` 复核；
  5. 对同类脚本（probe_*/debug_*/sniff_*）全量复查是否还有别的平台凭证。

### H-1 微信扫码登录在生产环境静默降级为 mock，身份验证失效（SEC-03）
- **位置**：`backend/app/api/v1/wechat.py:76-105`；部署 `.env` 无 `WECHAT_APPID/WECHAT_SECRET`
- **证据**：`_exchange_code` 仅在环境变量同时存在时才调微信 code2session，否则 `return {"openid": f"mock-{code}", ...}`（wechat.py:104-105）。部署 .env 未配置微信密钥 → 生产实际走 mock 分支。
- **影响**：任意人可伪称任意身份（openid 完全客户端可控）；`code-login` 为匿名端点；可无限创建 pending 注册申请灌爆审批队列。
- **建议**：生产未配置微信 AppID/Secret 时应 fail-fast 或显式开关 `WECHAT_MOCK_ALLOWED`（默认 False）；mock 仅允许 dev/test 生效。

### H-2 报销审批可绕过 + 同一发票可重复报销（API-01/API-02）
- **位置**：`backend/app/api/v1/invoices.py:259-292`；`backend/app/models/expense.py:61-72`
- **证据**：
  - `create_reimbursement` 为 CurrentUser，`status=payload.get("status", "待审核")` —— 客户端可直接传 `已通过` 绕过主管审核；
  - `approve_reimbursement` 接受任意 status 且不校验当前状态；
  - `ReimbursementItem.invoice_id` 仅 index 无 unique；`if i.status != "已报销"` 置为"已入账"，而全库**无任何代码把发票置为"已报销"** → 发票可被反复加入新报销单，同一张发票多次报销（资金损失）。
- **建议**：新建恒为"待审核"；approve 校验 待审核→已通过/已驳回；审核通过时把发票置为"已报销"；`reimbursement_items.invoice_id` 加 UNIQUE；存量重复关联清洗。

### H-3 微信注册可申请任意角色（含 admin）提权（SEC-04）
- **位置**：`backend/app/api/v1/wechat.py:54-62, 279`
- **证据**：`desired_role` 为自由 str 无枚举校验；审批通过时 `role=payload.assign_role or reg.desired_role or ...` 原样入库；`User.role` 为 String(32) 无 DB 约束，`require_role` 按字符串比对。
- **影响**：mock 模式匿名提交 `desired_role=admin` → 管理员审批通过即获系统管理员。
- **建议**：角色用枚举校验并限制低权限；审批时管理员显式指定角色；UI 高亮申请角色与默认差异。

### H-4 JWT 密钥为占位短语 + fail-fast 可绕过 + 派生 Fernet 加密（SEC-01）
- **位置**：`backend/.env`（JWT_SECRET_KEY len=68，前缀 "ple***"，含 please/change/random 占位词）；`backend/app/core/config.py:97`（仅 `==` 精确比对默认串）；`backend/app/core/crypto.py:16-19`（CONFIG_ENCRYPTION_KEY 为空 → Fernet 密钥由 JWT_SECRET_KEY 派生）
- **影响**：密钥疑似可猜占位短语；改一个字符即可通过 fail-fast；一旦泄露可伪造任意用户 token，且 BMS/SCRM 平台凭证加密一并失效。
- **建议**：fail-fast 升级为强度校验（长度≥32 且拒占位词）；为生产生成随机密钥并设置独立 CONFIG_ENCRYPTION_KEY；轮换后重加密存量凭证。

### H-5 上传记录/解析/导入无属主与角色控制（SEC-05）
- **位置**：`backend/app/api/v1/uploads.py:47-73,107-152,195-222`；`backend/app/schemas/upload.py:86`
- **证据**：`list_records` 用 `_: CurrentUser` 且仅按 data_type/source 过滤；`parse_upload` 可对任意 stored_path 返回前 10 行真实数据（含手机号/金额）；`confirm_import` 可对任意文件执行批量写库。
- **影响**：任意登录用户可枚举全部上传记录、读取他人 PII、对他人文件重复导入造成数据覆盖/重复。
- **建议**：按属主/角色做数据范围过滤；import 收敛为 ManagerUser 并校验文件归属。

### H-6 审计贴图在生产（及开发）环境 404 —— nginx 正则遮蔽 /uploads（OPS + 主代理核实）
- **位置**：`web/nginx.conf`（`location ~* \.(js|css|png|jpg|...)$` 正则 vs `location /uploads/` 前缀）；`backend/app/core/storage.py:76`（URL 为 `/uploads/audit_attachments/...png`）；`web/vite.config.js`（dev 代理仅 `/api`）
- **证据**：nginx location 选择规则：正则 location 优先级高于普通前缀 location。`/uploads/audit_attachments/1/xxx.png` 命中正则分支（该分支只有 add_header，从 `/usr/share/nginx/html` 找文件）→ 404；dev 下 vite 无 /uploads 代理 → 同样打不开。
- **影响**：审计贴图（报告/跟进/审计附带的图片证据）在生产与开发环境均无法展示。
- **建议**：`location /uploads/` 改为 `location ^~ /uploads/`（或用 `location ~* ^/uploads/` 排除）；vite.config.js 增加 `/uploads` 代理。

### H-7 首次建管理员把真实初始密码写入持久化日志（SEC-02）
- **位置**：`backend/app/main.py:162`
- **证据**：`logger.info(f"已创建默认管理员: {settings.INIT_ADMIN_USERNAME} / {settings.INIT_ADMIN_PASSWORD}")` 明文打印密码，落入挂载的 `./logs/backend` 与 docker json-file。
- **建议**：删除密码输出；只记录用户名。

### H-8 任意登录用户可改异常状态/直接闭环（API-03）
- **位置**：`backend/app/api/v1/incidents.py:222-252`
- **证据**：`add_followup` 用 CurrentUser，payload 带 status 时直接覆盖 `Incident.status`（仅枚举校验、无转移合法性），还可 is_closed 闭环。
- **建议**：followup 仅记录不转状态；状态变更要求 AdminOrSupervisor + 白名单转移表。

### H-9 今日看板筛选参数被静默忽略（API-07）
- **位置**：`backend/app/api/v1/analytics.py:187-259`
- **证据**：today/kpi、hourly-trend、reception、refund、queue 接受 department/group_id/specialty_id 参数但未传给服务、缓存 key 也不含——前端按部门/组筛选拿到全量数据，且不同筛选命中同一缓存。
- **建议**：透传参数并入缓存 key，或删除无效参数。
