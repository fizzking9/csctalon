# 外部投诉「同源判重」规则原型验证报告 (2026-09-09)

> 脚本: `scripts/complaint_same_source_proto.py`(v1) / `complaint_same_source_v2.py`(v2, 融合客服标注) / `complaint_same_source_v3.py`(v3, **同SN主键, 用户最终口径**)
> 数据: 本地库 external_complaints 真实主批次 id<300000（2622 行）
> 口径演进: v1 同手机号+内容相似 → v2 +客服标注(N)/重复词/同工单 → v3 **同SN+内容高相似+时间近(用户拍板最终口径)**

## 判重规则（原型实现）

| 维度 | 规则 |
|---|---|
| 关联键 | complainant_phone 非空用手机号；空则退化 device_sn |
| 时间窗 | 两行 complaint_date 差 ≤ 14 天 |
| 渠道簇 | 市监局各监所同簇(航城/宝安/南沙/天河/武汉)；12315/消协同簇(全国12315/全国消协/消协315)；公共服务平台/消委会/内部各成簇 |
| 内容相似 | 归一化(去手机号/SN/标点/停用词) + 字符2-gram Dice 与 公共子串 ratio 取高 |
| 阈值 | 跨簇(真多渠道) Dice≥0.45；同簇需 ≥0.62 |

## 结论

1. **规则启发式可行**：76 组候选里 ≥0.79 的约 60 组（80%）是**高可信同源**（大量逐字重复 + 跨渠道），可自动并入。
2. **0.45~0.69 边界区是规则与人工的分界**：该区间混有"真同源但措辞差异大"(如 1831↔1843、1736↔1738、1509↔1517，语义同源但字符 sim 低) 与"同人不同诉求"(如 904↔942、1347↔1357)，**纯字符相似度无法可靠区分** → 需引入语义(轻量关键词/同义)或人工复核。
3. **渠道簇有效**：把航城监所/宝安市监局等归入"市监局簇"后，跨"渠道"判重能抓住 12315↔市监局 这类用户主场景；若不做簇，同是"市监局"不同监所的行会被误当"不同渠道"漏判。

## 规则调优建议（下一步若实现功能）

1. **主判**：sim≥0.79 → 自动同源（高置信）。
2. **边界**：0.45≤sim<0.79 且 **跨渠道簇** → 提升为"需人工复核"候选，UI 呈现供一键确认/驳回。
3. **同簇低 sim**（0.45~0.62 且同渠道簇）→ 大概率同人不同诉求，不自动并入（降噪）。
4. **语义增强**：对 `虚标/虚假/假信息/涨价/退款/乱扣` 等投诉主题词做归一映射，可显著提升 `1831↔1843` 这类措辞变体同源的召回（字符 0.49 → 语义应判同源）。
5. **SN 退化**：`17384↔2465` 证明同内容可能 SN 不同，SN 只能作弱辅助，不能作强排除。

# v2 补充：客服登记信号 + 融合规则 (2026-09-09)

## 客服登记信号（用户补充）

客服登记时在 complainant 姓名后加括弧数字标注（如 `王杰（2）`、`胡康玲（3）`），或注明"重复投诉"。

### 语义澄清（关键）
- 真实批次 143 行带 (N) 标注，涉及 104 手机号（142 行有手机号、139 行有 SN → 手机号可作主键）。
- **实测 (N) 是"同投诉人(同手机号)第 N 次投诉"的总序号**，跨时可达数月~1年（如 `胡阳` 187****6503，9 行跨 2025-03~2026-07、多 SN 多事件、标 2/3/4/5/6/8）。
- **不能简单把 (N) 当"同一投诉重复登记"直接合并**，否则会把同一人一年内多起不同事件误并成 1 案。
- 真·同源形态 = 同 SN + **同关联工单** + 相邻几天 + 跨渠道：`胡康玲/（2）/（3）`(同工单 GD845132894099030016)、`赵梓颐/（2）/（3）`(同工单 GD846178622409883648)、`王杰（2）`(同工单 GD849772949094612992)。
- result=`重复投诉` 28 行；problem/明细含`重复/再次/重新投诉` 143 行（强信号）；"再次来电补充"多为同一事件过程追加，需甄别。

## v2 规则（证据打分）
候选键: 同手机号(主)/同SN(辅) + 日期差≤14天。对每对打分：
- S1 客服标注(N)同名(去标注后基准姓名同 且 至少一行带N)=+60；同名无标注=+20
- S2 result=`重复投诉`=+80
- S3 内容含`重复/再次投诉/重新投诉`=+40
- S4 **同关联工单**(matched_ticket_no 相同)=+50（同工单=同案铁证）
- S5 内容相似 ≥0.8→+50；0.6~0.8→+25
- S6 跨渠道簇=+10
判定：总分≥90 高置信；60~90 中置信-需复核；≥60 输出。

## v2 结果
- **命中 115 对**（≥90 高置信 70 对 + 60~90 中置信 45 对）
- **对客服标注真值(≤14天 102对)召回 63 → 62%**（v1 内容相似仅 37%）
- 高置信样例全为"客服标注(N)同名 + 同工单/内容高相似/跨渠道"，质量高：
  `易国梁(2)↔(3)`(同工单+result重复投诉+内容0.25但同工单)、`胡康玲(2)↔(3)`(同工单+跨渠道)、`赵梓颐(2)↔(3)`、`王杰(2)↔王杰`(同日同工单双行真重复)
- 中置信边界仍含少量"同人跨多月不同案"（`胡阳(3)↔(4)`、`徐良(3)↔(4)` 同工单但跨 13 天以上）→ 需以"同工单+时间窗"或人工复核兜底

## v2 结论与建议
1. **同关联工单 = 最强同源信号**（315 多行指向同一工单 = 同一案件多渠道/多登记），且工单侧 `已完成` 是最权威 handled 证据。
2. 判重主信号应改为：同手机号 + 归一化姓名 + 同工单 + result=重复投诉 + 内容重复词；内容相似仅辅助。
3. 剩余召回缺口（102-63=39 对）主要是"客服标注(N)但同人跨多月不同工单" → 是否算同源需业务口径（建议不算，属同人多次投诉非重复登记）。
4. 建议落地：同工单→自动同源；客服(N)同名+跨渠道+内容相似→高置信；其余→人工复核。

# v3 补充：用户最终口径 = 同SN为主键 (2026-09-09)

## 用户口径（决定性，修正 v2 过宽）
- **同源(重复登记) = 同SN(设备) + 内容高度相似 + 时间跨度不久** → 合并(可同时关闭)
- 渠道不同 = "重复投诉"特征（同件事多渠道），但仅渠道不同不够；手机号/姓名仅作参考区分
- **不同SN即便同人 = 不同投诉**（胡阳例：3个SN=3起独立案，不合并）
- **同SN但内容不同/跨久/不同诉求 = 不同投诉**（徐良例：1940后台账单 vs 1992 iccid 不合并）
- 无SN退化: 同手机号 + 内容相似≥0.8 + (同工单 或 ≤14天) 才谨慎同源

## v3 规则（同SN主键）
主键: 同 device_sn。条件: 同SN + 内容相似≥0.7 + 日期差≤30天 → 同源。
辅助线索(仅标注, 不单独判): 客服(N)标注 / result=重复投诉 / 跨渠道 / 同工单。

## v3 结果（脚本 complaint_same_source_v3.py）
- **46 对**（同SN 35 + 无SN退化 11）
- **胡阳/徐良均被正确排除**（不同SN / 同SN不同诉求）→ 用户口径验证通过
- 保留全为真重复登记：同SN+高相似+客服标注(N)/跨渠道/同工单叠加（王建宇/覃春燕/郑沛垚/易国梁/吴宇萱/马原/孔安其/方鹤玲/韦桂/杨飞…）
- 时间窗边界待确认: 梁先生20天/金先生15天/(南沙市监局)19天 是否仍算"跨度不久"
- 姓名异常待核: 张帆↔刘佳奇(同SN同内容sim1.00但姓名不同)
- 导出: data/外部投诉同源候选_v3_20260909.xlsx

## 公共服务平台"再次来电内嵌前文"陷阱（重要发现）
- 公共服务平台 508 行：65 行 problem 含 `<br/>`(多段内嵌)、11 行"再次来电"；全平台 304 行 problem>300字
- 形态：每次"市民再次来电补充"把前次投诉原文整段复制在 problem 里（如刘桂梅投诉8~15次、梁先生）

- **处理：命中"再次来电/投诉N次/内嵌"特征 且 problem>150字 → 降为 NEED_REVIEW 人工，不自动并**

## v4 FINAL 规则（脚本 complaint_same_source_final.py）
```
同源(AUTO) ⇔ 同 device_sn + 内容相似≥0.7 + 日期差≤30天

无SN退化: 同手机号 + 相似≥0.8 + (同工单 或 ≤14天), 同样排除内嵌前文
```
