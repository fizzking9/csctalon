## 六、关于「手改源文档」的结论（重要）

用户已手工修订腾讯文档中的明显错误日期与空白日期。**但库不会跟随源文档删除**：

```python
dedup_hash = md5(日期 | 手机 | SN | 问题签名)      # 身份指纹
同步 = pg_insert(...).on_conflict_do_update(...)   # ← 无 DELETE 分支
```

| 源文档操作 | 库的结果 |
|---|---|
| 删除一行 | 库里**残留** |
| **修改内容** | 指纹变 → **INSERT 新行**，旧行残留 ← **反而制造重复** |

⚠️ 后者正是 2026-09-05 那次 2,527 行重复导入的成因（日期转置 → 指纹变 → 新增而非更新）。

→ 「源文档对齐」需架构级变更（软删 + 连续 N 次未出现才确认）。且 #42 记载
   「上游推送会丢失编号 53%」，说明上游本身不稳定，**贸然跟随删除风险高**。
