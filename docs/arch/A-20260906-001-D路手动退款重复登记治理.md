## 一、背景与问题（生产实证 2026-09-06）

- `manual_refunds` 全表 **5,829 行 / 仅 2,878 个去重 order_no**（超额 2,951 行 / ¥444,066）。
- 典型脏数据：同一 `order_no` 两行 —— 无SN行（`device_sn` 空、金额恒 100、`register_time` 乱年份 2001~2005/2031 的 09-26、`remark`=余额已清除/押金）+ 有SN真实行。
- `backfill_d_op_time`（reconcile.py）L1(order_no) 把同一 E 水单 report 回填到 2~5 行 manual（1,594 report → 3,201 行 / ¥365,177），无SN残留行被 `COALESCE(op_time,register_time)` 拉进近期窗口 → D 路重复计入经营。
- 量化：8月对账差 +¥203,686 ≈ D 重复 ¥202,970；9/1~9/5 +¥48,219 ≈ ¥49,228（348 行, 97% 无SN）。

## 三、处理设计

### 3.1 backfill_d_op_time 护栏（reconcile.py，P1）
1. 候选 manual 排除"无SN + register_time 乱年份(非 2025~2026 区间)"的残留行 → 不自动回填，标 `quality_status=pending` 待人工。
2. 唯一候选强制：同一 report（`backfill_manual_refund_id` 已置位）不再回填其它 manual 行（幂等护栏）。
3. 多候选命中 → pending（沿用现逻辑）。
4. 溯源/幂等不变：`quality_status=auto_filled` + `backfill_refund_record_report_id` 双向溯源。

### 3.2 历史脏数据治理（P2，一次性脚本）【v1.1 修订】

**v1.0 口径（已废弃）**：`is_refunded='是'` AND `device_sn` 空 AND `register_time` 年份 ∈ [2001..2024]∪{2031} AND 与同 order_no 有SN真实行成对。

> ⚠️ **v1.1 废弃原因（生产预览实证）**：该口径在候选 MM-DD 指纹 `{07-26,08-26,09-26}` 上会命中
> **2,134 行 / ¥320,929**，但抽样发现大量无SN行的金额 = 该 order 在 E 水单的**多笔退款合计**
> （如某 order E 两笔 20.00+7.80=27.80，无SN行恰记 27.80）——这些是**真实的多批次退款汇总登记**，
> 并非重复。一刀切标记会**误伤真实台账**（含"威胁315投诉/要投诉工信部"等真实客诉退款）。

**v1.1 口径（用户裁定，现行）**：仅治理**确凿重复** ——
- `is_refunded='是'` AND `backfill_refund_record_report_id` 非空
- 且该 report 被 **≥2 行 manual 引用**（同 `backfill_refund_record_report_id` 一对多回填产物 = 同一笔真实退款被记多行）
- 每组保留 1 行（优先有SN + id 最小），其余标 `quality_status=duplicate_residual`
- 处理：**不物理删除**，标 `quality_status=duplicate_residual` + `quality_note`(写 reason + 保留行 id)，可回滚。
- 规模：1,585 行 / ¥206,854.60（1594 组一对多 report 中的超额行）。
- 若后续需统计排除 → 走口径评审更新 LOCKED 文档（不在本次静默改）。

### 3.3 防复发（P3）
- `upsert_manual_refunds` 质量校验：无SN + 乱年份入参 → 标 pending / 拒收。
- 巡检：`manual_refunds` 异常年份行计数（可挂 A-20260904-001 健康告警扩展，二期）。

## 五、风险清单

1. **过度治理风险（v1.1 已修正）**："无SN+年份异常"一刀切会误伤真实多批次汇总登记行（生产预览实证：
   无SN行金额可=E 该 order 多笔退款合计）→ v1.1 收紧为仅"同 report 一对多"确凿重复。
2. 排除"无SN+乱年份"可能漏真实无SN登记 → 转 pending 人工（ManualRefundQuality 已有 confirm/fix）。
3. 治理标记若影响统计口径 → 必须先评审 LOCKED 文档（A-20260902-011），禁止静默改。
4. D 台账与 E 水单是**多对多**（一 order 多次退款, 台账或合并记或分笔记）→ 治理只消除确凿重复,
   不追求 D=E(对账偏差本就是"登记 vs 实际扣款"的正常差异, 用 #22 复核功能人工核对)。
