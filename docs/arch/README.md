# 架构文档（Arch）— 锁定目录

**生效日期**：2026-09-01
**用途**：存放**已锁定**的架构设计文档（对应"AI 协作治理规范" 4.2 / 4.3）
**关联文档**：AGENTS.md（全局约束，其中"禁止擅自修改已锁定架构文档"）

> ⚠️ 本目录下的文件默认视为 **LOCKED（锁定）**。AI 助手不得擅自修改；
> 修改必须先经人工审核，更新后重新标记版本并打 tag。

---

## 目录规范

| 项 | 约定 |
|---|---|
| 命名 | `A-YYYYMMDD-序号-简述.md`（如 `A-20260901-001-退款查询接口.md`） |
| 锁定标记 | 文件头部标注 `状态: LOCKED` + 版本号 |
| git tag | 锁定后打 `arch/A-YYYYMMDD-序号` 标签 |
| 修改 | 人工审核 → 更新文件 → 版本号 +1 → 重新打 tag |

## 阶段切换 SOP（对应 4.3）

1. 需求确认 → **Architect** 阶段 → 产出架构文档（放本目录）
2. 人工审核架构文档 → **锁定**（标记 LOCKED + 打 `arch/` tag）
3. 切 **Developer** 阶段 → 基于本目录已锁定文档开发（禁止自行改架构）
4. 开发完成 → commit → 切 **Reviewer** 阶段 → 审查报告（见 docs/standards/review-checklist.md）
5. 报告无 CRITICAL → 人工终审 → 合并
6. 有 CRITICAL → 切回 Developer 修复 → 重新审查

> 关键：阶段切换时必须清空上一轮上下文（新建会话），防止 AI 把架构阶段假设带到开发阶段。
