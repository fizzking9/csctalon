## 〇、范围与边界

用户诉求：日报等只读数据（参考 workbuddy 输出的退款/投诉日报）由**本地部署的 27B 级模型**分析，界面以**右上角/右侧辅助助手**形式"提问 → 分析输出"，且随只读接口扩展而扩展。

**本设计覆盖**：
- 数据底座：给模型喂什么（内部聚合 feed，非 external token 通道）
- LLM 网关：本地模型服务（Ollama/vLLM，OpenAI 兼容）接入
- 任务执行：几十秒生成的长耗时处理（轮询模式，与现有 SyncTaskManager 同构）
- 前端助手：MainLayout 右上角入口 + 抽屉会话（Markdown 安全渲染）
- 配置/安全/角色/两期划分/风险/测试

**不覆盖**（边界）：
- 不引入 Celery/独立队列/SSE 长连接（一期；SSE 作二期可选增强）
- 不做行级 PII 明细喂模型（只喂聚合脱敏指标）
- 不把 external token 鉴权链路用于内部助手（内部助手走登录用户 ManagerUser + 内部聚合）
- 不动 27B 推理服务器本身的部署（由 OPS/硬件决定；本设计只定义我方调用契约）

## 二、数据底座（喂给模型的内部 feed）

> ⚠️ **内部 AI 助手不走 external `/brief`**（那是外部工具数据底座，带 token scope/限频/审计）。直接在后端 service 层复用内部聚合并命中同一 Redis 缓存 key。

**一期 feed 段**（`ai_feed.py` 或 `ai_assistant` service 组装，统一口径复用既有聚合，不另起炉灶）：

| 段 | 来源（service 复用） | 内容 |
|---|---|---|
| `reception` | `A.today_kpi` + `external._reception_specialty` 同口径（考虑上提为内部 service） | 当日/周期接待量、设备数、各专项名单/会话/设备 |
| `refund` | `A.today_kpi` + `A.refund_decision_overview`（同窗口） | 四路 A/B/C/D 金额笔数 + E 现金流 + 涉诉率/涉诉金额 + 环比 |
| `complaint` | `complaints._sources_reg_handled`（2026-09-04 已实现三源 registered/handled/backlog）+ backlog | 内部/商户号/外部 三源登记/处理/积压 |
| `_spec` | 各段口径说明（金额单位=元、时间口径等） | 供模型理解语义，减少幻觉 |

**Feed 组装**：
- 输入窗口：`period`（daily/weekly/monthly）+ `date` → `start/end`（复用 `_resolve_windows` 语义；今天=实时截止 now）。
- 环比：复用 `today_kpi` 自带 `yoy_value/yoy_pct`。
- 长度上限：按 `settings.AI_ANALYZE_MAX_CHARS`（默认 6000）裁剪/聚合，防 token 超限与延迟。
- 缓存：命中现有 `today:kpi / refund:do / complaint:*` 缓存 key（同一 TTL），不额外失效。

## 三、LLM 网关（`backend/app/services/llm_client.py`）

**契约**：OpenAI 兼容 `POST {LLM_BASE_URL}/v1/chat/completions`（Ollama / vLLM 均支持）。

```python
# 参考 ai_acc_fetcher(错误分级+退避) / scrm_client(长活 client)
async def chat_completion(messages, temperature=0.2, max_tokens=...) -> str
async def chat_completion_stream(...) -> AsyncIterator[str]   # 二期 SSE 可选
```

- **模型选择**：默认 `LLM_MODEL`（如 `qwen2.5:27b` / vLLM served model）；一期固定日报/简报可用**模板+小模型或规则**，二期自由问答用 27B（见 §七 两期）。
- **错误分级**：5xx/429/超时 → transient（指数退避重试 `LLM_RETRY_MAX/BASE/CAP`）；4xx（不含 429）→ permanent 不重试。
- **超时**：`httpx.Timeout(connect=10, read=LLM_TIMEOUT_S)`（生成几十秒，read 单独放宽，默认 120s）。
- **单 worker 注意**：async httpx 直接 await（I/O 型）；若本地模型服务是同步推理（CPU/GPU 高占用）需 `asyncio.to_thread` 提交，避免卡事件循环（仿 cache_warmer 线程池用法）。

## 四、任务执行（AiTaskManager，仿 SyncTaskManager）

长耗时（几十秒~分钟）不占用 HTTP 连接等待：

- 内存单例 `AiTaskManager`（单 worker 保证互斥，同 `sync_task_manager`）：
  - `AiTask(task_id, status: queued|running|success|failed, prompt, result_md, error, created_at, finished_at)`，历史保留 N 条。
- **接口契约**：

| 方法/路径 | 说明 |
|---|---|
| `POST /api/v1/ai/analyze` | 入参 `{question?, scope: 'daily_report'|'refund'|'complaint'|..., period: 'daily'|'weekly'|'monthly', date?}`（或自由文本问句 + 范围）。鉴权 `ManagerUser`。→ 创建任务返回 `{task_id}`（模型较慢时任务式） |
| `GET /api/v1/ai/tasks/{task_id}` | 轮询返回 `{status, result_md, error}`；终态保留 5~10 分钟 |
| `GET /api/v1/ai/config` | 助手是否启用（LLM_ENABLED）+ 可用 scope 选项（内部；`ManagerUser`） |
| `POST /api/v1/ai/templates/run`（可选一期） | 固定日报模板一键生成（内部等价 daily brief，不经模型/或模型润色） |

- 前端轮询：抽屉打开任务后 `setInterval` 2s 轮询（复刻 SyncDashboard 轮询 + MainLayout 顶部进度条模式），终态停止。

## 六、安全 / 权限 / 配置

### 6.1 权限
- 执行会话/简报读全量经营指标 → **`ManagerUser`**（admin/supervisor/specialty_lead，与看板管理口径一致）。
- 模型开关/配置管理（LLM_ENABLED、base_url 等）→ 环境变量 `AdminUser`（配置仅 env，不走 UI 改）。
- 入口按钮前端 `authStore.isManager` 显隐。

### 6.2 配置（`backend/app/core/config.py` 新增组，命名对齐惯例）

```python
# ── 本地 LLM / AI 分析助手(A-20260904-003 PENDING) ──
LLM_ENABLED: bool = False          # false 时 ai 端点 503(仿 EXTERNAL_API_ENABLED)
LLM_BASE_URL: str = ""             # 本地模型服务地址(如 http://127.0.0.1:8001)
LLM_API_KEY: str = ""              # 经环境变量注入, 严禁硬编码/入库
LLM_MODEL: str = ""                # 模型名(如 qwen2.5:27b)
LLM_TIMEOUT_S: float = 120.0       # 生成 read 超时(秒)
LLM_RETRY_MAX: int = 2
LLM_RETRY_BASE_S: float = 1.0
LLM_RETRY_CAP_S: float = 30.0
AI_ANALYZE_MAX_CHARS: int = 6000   # 数据底座长度上限
AI_TASK_TTL_S: int = 600           # 任务结果保留
AI_TASK_HISTORY: int = 20          # 内存保留任务数
```

### 6.3 安全
- 模型只收聚合指标 + `_spec`，**不喂 PII 明细**（SN/手机号/投诉原文等）。
- 输出仅作参考：助手回复前加"数据截至/口径"提示；Prompt 固定模板约束只基于给定 feed 作答、不编造。
- 内部端点登录鉴权 + 角色；不做 external token。
- LLM_API_KEY 若本地无鉴权可留空（仅内网），但生产 env 建议配置并加 prod fail-fast（若 LLM_ENABLED 则 base_url/api_key 必填）。

## 八、风险清单

1. **27B 本地推理性能**：无 GPU/显存不足时单次日报可能 >1 分钟。缓解：任务轮询不阻塞；一期模板不经模型；二期量化 + `LLM_TIMEOUT_S` 放宽；可降级 7B~14B。
2. **模型幻觉/口径漂移**：模型可能编造数字。缓解：只喂聚合 feed + `_spec`，Prompt 约束"仅基于给定数据作答，无数据写'暂无'"；输出附口径与时间戳。
3. **数据底座与聚合漂移**：若复用 `today_kpi/refund_decision_overview/complaints` 口径/键名变更会波及 AI 输出。缓解：feed 层独立 schema 重组（不透传整包），聚合改动时 feed 适配；沿用现有测试锁口径。
4. **单 worker 阻塞**：同步/重推理卡事件循环。缓解：async httpx + 必要时 `asyncio.to_thread`；限并发（同刻 1 任务，队列）。
5. **Markdown XSS**：模型输出可能含恶意/异常标签。缓解：一律 `renderMarkdown` 消毒；不用裸 v-html。
6. **PII 泄漏**：自由问句若引导模型复述明细。缓解：feed 不含明细级 PII；如必要在网关过滤。
7. **代理缓冲**：若做 SSE（二期）经 frp/nginx 需确认不缓冲；一期轮询无此问题。
