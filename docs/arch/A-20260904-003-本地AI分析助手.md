## 〇、范围与边界

用户诉求：经营只读数据（reception/refund/complaint，与对外 brief 同口径、workbuddy 已验证）由 LLM 分析，界面右上角辅助助手"提问 → 分析输出"，参考 workbuddy 退款/投诉日报输出形态；模型一期 DeepSeek（云），后续可切本地私有化。

**本设计覆盖**：
- 数据底座：内部聚合 feed（与 external brief 同底层函数/同缓存，登录用户直连，不走 external token）
- 业务口径上下文：口径卡(Business Glossary)抽取自已落地口径，随 Prompt 注入
- LLM 网关：OpenAI 兼容客户端（DeepSeek 官方 / 本地 Ollama-vLLM 均可，配置可插拔）
- 任务执行：几十秒生成的长耗时处理（轮询模式，与现有 SyncTaskManager 同构）
- 前端助手：MainLayout 右上角入口 + 抽屉会话（Markdown 安全渲染）
- 配置/安全/角色/分期/风险/测试

**不覆盖**（边界）：
- 不引入 Celery/独立队列/SSE 长连接（一期；SSE 作二期可选增强）
- 不做行级 PII 明细喂模型（只喂聚合脱敏指标）
- 不把 external token 鉴权链路用于内部助手（内部助手走登录用户 ManagerUser + 内部聚合）
- 不负责 DeepSeek/本地推理服务的账号与部署（DeepSeek key 用户开；本地推理由 OPS/硬件决定）

## 二、数据底座（喂给模型的内部 feed）

> ⚠️ **内部 AI 助手不走 external `/brief` HTTP**（那是外部工具数据底座，带 token scope/限频/审计）。本期（终审 A）：**内部 service 直连聚合**——调 `today_kpi / refund_decision_overview / complaints._sources_reg_handled`（与 external brief **同一底层函数、同一 Redis 缓存 key**），登录用户 JWT + ManagerUser，无 token/限频/HTTP 双跳。数据维度即对外那几块（reception/refund/complaint），workbuddy 已验证、口径逐字段一致。

**feed 段**（`ai_feed.py` 组装，统一口径复用既有聚合，不另起炉灶）：

| 段 | 来源（service 复用） | 内容 |
|---|---|---|
| `reception` | `A.today_kpi` + 接待专项（`external._reception_specialty` 同口径，实现时上提为内部 service 或复用其逻辑） | 当日/周期接待量、设备数、各专项名单/会话/设备 |
| `refund` | `A.today_kpi` + `A.refund_decision_overview`（同窗口） | 四路 A/B/C/D 金额笔数 + E 现金流 + 涉诉率/涉诉金额 + 环比 |
| `complaint` | `complaints._sources_reg_handled`（2026-09-04 已实现三源 registered/handled）+ backlog | 内部/商户号/外部 三源登记/处理/积压 |
| `_spec` | 各段口径说明（金额单位=元、时间口径等） | 供模型理解语义，减少幻觉 |

**Feed 组装**：
- 输入窗口：`period`（daily/weekly/monthly）+ `date` → `start/end`（复用 `_resolve_windows` 语义；今天=实时截止 now）。
- 环比：复用 `today_kpi` 自带 `yoy_value/yoy_pct`。
- 长度上限：按 `settings.AI_ANALYZE_MAX_CHARS`（默认 6000）裁剪/聚合，防 token 超限与延迟。
- 缓存：命中现有 `today:kpi / refund:do / complaint:*` 缓存 key（同一 TTL），不额外失效。

## 二·A、业务口径上下文（Business Glossary）—— 回答问题"是否把规划业务逻辑做成上下文"

**结论：不整篇灌《规划设计》，而是把"模型必须遵守的统计口径"抽取成分层上下文**，避免大文本稀释关键口径/抬高成本/带偏回答。

### Prompt 三层结构（每请求组装）

```
┌─ System（固定）─────────────────────┐
│ 角色=经营数据分析助手; 铁律=数字必须来自给定│
│ 数据, 禁止编造/外推; 无数据→写"暂无";      │
│ 金额单位=元; 只答所问; 时间按给定窗口       │
├─ Business Context（口径卡子集, 随问句选）──┤
│  · 投诉三源/登记/处理/积压                 │
│  · 退款四路 A/B/C/D + E + 涉诉率          │
│  · 接待会话/设备口径                     │
├─ Data（本请求 feed JSON + _spec + 环比）──┤
└─ User Query（自由问句）─────────────────┘
```

### 口径卡（`ai_glossary.py` 代码常量，key→短句）
从**已落地口径**（`_complaint_source_type_case`、registered/handled、四路定义等）提炼，例：
- `complaint_sources`：投诉三源 = 内部(商品/服务投诉) / **商户号(微信投诉, 独立单列)** / 外部(平台词 + 315 + 卡商群)
- `complaint_reg_handled`：登记=窗口内新增(register)；处理=窗口内真实完成(finish≥register+3min, 含历史单今日办结)；积压=窗口内登记未闭环
- `refund_routes`：退款 = A线上直退 + B钱包提现 + C闪猫 + D手动；E=refund_record_reports 退款成功(对账基准, 不累加, 2026-09-05 起替代 merchant_refunds)；涉诉率=涉诉金额/A路金额
- `timezone`：所有时间按 Asia/Shanghai 窗口；今天=实时截止 now

口径卡**与模板分离**、可 git 版本化；未来口径变更只改对应 key，不影响其它层。一期放代码常量（避开 preset seed 覆盖用户改动的坑）；二期有后台需求再 DB 化。

### 问答路由（本期=自由问答）
- 一期不预设"日报/周报"整篇模板（终审改为**先只做自由问答**）。
- 每次自由问句：先做**轻量路由**（关键词匹配，如 退款/投诉/接待 → 选相关口径卡子集 + 对应 feed 段），未命中则带全量口径卡 + 全量 feed。
- 可选后续：把 workbuddy 式日报输出固化为一套"展示模板 + 触发问句"放代码（二期），复用同一 feed/口径卡。

## 三、LLM 网关（`backend/app/services/llm_client.py`）

**契约**：OpenAI 兼容 `POST {LLM_BASE_URL}/chat/completions`。**约定 `LLM_BASE_URL` 给“完整前缀”(是否含 `/v1` 以服务商为准)，llm_client 统一在其后拼 `/chat/completions`**：
- DeepSeek 官方：`LLM_BASE_URL=https://api.deepseek.com`（**不带 `/v1`**，路径即 `/chat/completions`，实测文档 curl）
- 本地 Ollama/vLLM：`LLM_BASE_URL=http://127.0.0.1:11434/v1`（带 `/v1`）

```python
# 参考 ai_acc_fetcher(错误分级+退避) / scrm_client(长活 client)
async def chat_completion(messages, temperature=0.2, max_tokens=...) -> str
async def chat_completion_stream(...) -> AsyncIterator[str]   # 二期 SSE 可选
```

- **模型可插拔（终审）**：一期默认 **DeepSeek V4 Flash 官方 API**（`LLM_BASE_URL=https://api.deepseek.com`、`LLM_MODEL=deepseek-v4-flash`、用户开 key 填 `LLM_API_KEY`）；二期切本地私有化（Ollama/vLLM）只需改 `LLM_BASE_URL`+`LLM_MODEL`，代码零改。
- **DeepSeek 思考模式（重要）**：DeepSeek 模型默认开启 `thinking`。我们场景是“喂数据+要求确定性输出”，应**关闭思考或将 `reasoning_effort` 设 low**（请求体带 `thinking:{type:"disabled"}` 或 `reasoning_effort:"low"`），以省 token/降延迟；llm_client 按配置可传。
- **错误分级**：5xx/429/超时 → transient（指数退避重试 `LLM_RETRY_MAX/BASE/CAP`）；4xx（不含 429，含鉴权失败）→ permanent 不重试。
- **超时**：`httpx.Timeout(connect=10, read=LLM_TIMEOUT_S)`（云端/本地生成几十秒，read 单独放宽，默认 120s）。
- **单 worker 注意**：async httpx 直接 await（I/O 型）；若未来接本地同步推理（CPU/GPU 高占用）需 `asyncio.to_thread` 提交，避免卡事件循环（仿 cache_warmer 线程池用法）。

## 四、任务执行（AiTaskManager，仿 SyncTaskManager）

长耗时（几十秒~分钟）不占用 HTTP 连接等待：

- 内存单例 `AiTaskManager`（单 worker 保证互斥，同 `sync_task_manager`）：
  - `AiTask(task_id, status: queued|running|success|failed, prompt, result_md, error, created_at, finished_at)`，历史保留 N 条。
- **接口契约**（本期=自由问答）：

| 方法/路径 | 说明 |
|---|---|
| `POST /api/v1/ai/analyze` | 入参 `{question: str, period: 'daily'|'weekly'|'monthly', date?}`。后端做轻量路由(关键词→口径卡子集+feed 段, 未命中带全量)；→ 创建任务返回 `{task_id}`(模型较慢时任务式) |
| `GET /api/v1/ai/tasks/{task_id}` | 轮询返回 `{status, result_md, error}`；终态保留 `AI_TASK_TTL_S` |
| `GET /api/v1/ai/config` | 助手是否启用(LLM_ENABLED)+ 可选口径说明(内部; `ManagerUser`) |
| `POST /api/v1/ai/templates/run`(二期) | 预留: workbuddy 式日报模板一键生成(复用 feed/口径卡, 二期模板库化后启用) |

- 前端轮询：抽屉打开任务后 `setInterval` 2s 轮询（复刻 SyncDashboard 轮询 + MainLayout 顶部进度条模式），终态停止。

### 6.2 配置（`backend/app/core/config.py` 新增组，命名对齐惯例）


### 6.3 安全
- 模型只收聚合指标 + 口径卡 + `_spec`，**不喂 PII 明细**（SN/手机号/投诉原文等）。
- 输出仅作参考：助手回复附"数据截至/口径"提示；System 铁律约束只基于给定 feed 作答、不编造、无数据写"暂无"。
- 内部端点登录鉴权 + `ManagerUser`；不做 external token。
- `LLM_API_KEY` 走环境变量注入（DeepSeek key 用户开，严禁硬编码/入库/进日志）；生产 `LLM_ENABLED=true` 时 base_url/api_key 建议 fail-fast（本地无鉴权服务可留空 key，仅内网）。

## 八、风险清单

1. **推理延迟/可用性**：一期 DeepSeek 云端受网络与额度影响(单次可能数秒~数十秒)；二期本地 27B 无 GPU 时更慢。缓解：任务轮询不阻塞；`LLM_TIMEOUT_S` 放宽；429/5xx 退避重试；`LLM_ENABLED=false` 优雅 503。
2. **模型幻觉/口径漂移**：模型可能编造数字。缓解：只喂聚合 feed + 口径卡 + `_spec`，System 铁律约束"仅基于给定数据作答，无数据写'暂无'"；输出附口径与时间戳；后续可加"关键数字仅引用 feed"校验(二期)。
3. **数据底座与聚合漂移**：若复用 `today_kpi/refund_decision_overview/complaints` 口径/键名变更会波及 AI 输出。缓解：feed 层独立 schema 重组（不透传整包），聚合改动时 feed 适配；沿用现有测试锁口径。
4. **单 worker 阻塞**：同步/重推理卡事件循环。缓解：async httpx + 必要时 `asyncio.to_thread`；限并发（同刻 1 任务，队列）。
5. **Markdown XSS**：模型输出可能含恶意/异常标签。缓解：一律 `renderMarkdown` 消毒；不用裸 v-html。
6. **PII 泄漏**：自由问句若引导模型复述明细。缓解：feed 不含明细级 PII；如必要在网关过滤。
7. **代理缓冲**：若做 SSE（二期）经 frp/nginx 需确认不缓冲；一期轮询无此问题。
