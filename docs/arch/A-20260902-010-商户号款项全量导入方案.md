# 商户号款项 Excel 全量保序导入方案

**状态**：LOCKED（v1.0）
**锁定日期**：20260902
**锁定脚本**：scripts/lock-arch-docs.sh


## Context（背景）

`01样本数据/商户号款项.xlsx` 是微信商户号交易流水（86,353 行：79,681 笔支付 + 6,671 笔退款 + 1 脏行）。用户希望导入这份数据。

排查发现按现有 schema 直接导入会严重损坏数据，已与用户确认采用「全量保序插入」策略：

1. **微信退款单号（wx_refund_no）被 Excel 存成 float64，28 位真实单号永久丢失**：6,671 笔退款按损坏值去重只剩 2,295 个，1,365 组碰撞（如 6 笔不同退款撞成同一 float）。
2. **79,681 笔支付行 wx_refund_no 全为 "0"**：作主键会塌缩成 1 行。
3. 模型当前以 `wx_refund_no` 为主键，而可靠键 `商户退款单号`（RF 前缀）不在模型字段里。

用户决策：把 `wx_refund_no` 降级为普通可空字段，加自增 `id` 主键，全量插入 86,353 行（支付+退款），后续拿到准确数据再按 `商户退款单号` 更新补全。DB `merchant_refunds` 表当前 0 行，迁移零风险。

   ```python
   run_upsert(df, 'merchant_refund', mapping, db)
   ```

- wx_refund_no 原值已损坏（float 截断 + 支付行为 "0"），仅作留存，不可作唯一键；约 1,000 行商户退款单号也是数值损坏型。
