# 时间字段统计规范修订

## Context(为什么做这次修改)

基于 2026-08-01 的全系统数据时间审核(报告见 `docs/数据时间审核报告.md`),确认时区修复已生效,但发现两类影响统计准确性的问题需要在代码层固化处理:

1. **SYS/system 排除的大小写 bug**:PostgreSQL `notin` 大小写敏感,`refunds.operator` 实际含 `system`(8132)和 `SYS`(5577)两种写法。3 个现金流/人员视图用 `["sys","system"]`(仅小写),**漏排 5577 条 SYS 系统退款**(退到会员钱包,非真实现金流出),导致金额虚高、人员工作量虚增。只有 `preset_cash_trend` 用了完整的 4 种写法。

2. **不可靠时间字段仍可被选用**:`ticket.finish_time` 与 `refund_wide.ticket_finish_time`(89% 是 BMS 批量覆盖/同步填充,非真实完成时间)、`refund.updated_at_raw`(被 03:15 SYS 批量覆盖)在数据源注册里仍是 `is_filterable=True`,用户在自助分析里可能误选,得出错误结论。

**目标**:把审核结论固化为代码规则 + 规范文档,使后续统计默认正确,不可靠字段不再被误用。

## 修改清单

### 1. `backend/app/services/preset_views_seed.py` — 修复 5 个预设视图

统一 SYS/system 排除清单为 `["sys", "system", "SYS", "System"]`(4 种写法,沿用 `preset_cash_trend` 既有模式)。

**A. 大小写补全(3 个视图,已有 notin 但写法不全)**:
- `preset_operator_refund`(L297):`["sys","system"]` → `["sys","system","SYS","System"]`
- `preset_cash_trend_v2`(L532):同上
- `preset_refund_operator_v2`(L573):同上

**B. 新增排除(2 个视图,本应排除但无 filter)**:
- `preset_refund_trend`(L16):segment filters 从 `[]` 改为:
  ```python
  "filters": [
      {"field": "refund_method", "op": "eq", "value": "线上"},
      {"field": "operator", "op": "is_not_null", "value": None},
      {"field": "operator", "op": "notin", "value": ["sys", "system", "SYS", "System"]},
  ],
  ```
  并更新 `description` 注明"仅线上、排除 sys/system 系统退款(真实退款趋势)"。与 `preset_cash_trend_v2`(金额视角)形成"笔数视角"互补。
- `preset_operator_ticket`(L242):filters 增加 `handler notin ["SYS", "客户"]`(SYS=6173 自动赠送工单、客户=283 客户自处理,均非真人客服工作量)。保留既有 `handler is_not_null`。
- `preset_refund_daily_detail_v2`(L609):filters 增加 `operator notin ["sys","system","SYS","System"]`(明细表,线上已退款的真实客服操作记录)。

### 2. `backend/app/services/data_source_registry.py` — 隐藏不可靠字段 + 加警告

在 `FIELD_OVERRIDES` 给以下字段设 `is_filterable=False` 并把 `field_name_cn` 改为带 ⚠️ 前缀(中文名在 `ensure_data_sources_registered` 里从模型 comment 反射,override 不直接改 name;改用 `description` 字段在 DataSource 表级补说明 + 在 FIELD_OVERRIDES 设 `is_filterable=False`)。

**字段**:
- `("ticket", "finish_time")`:加 `"is_filterable": False`
- `("refund_wide", "ticket_finish_time")`:加 `"is_filterable": False`
- `("refund", "updated_at_raw")`:加 `"is_filterable": False`

> 注:`is_filterable=False` 仅隐藏出筛选器/维度选择 UI,字段数据保留,直接 SQL 仍可查。`field_name_cn` 来自模型 comment 反射,要在模型层加 ⚠️ 警告需改 model 注释——为避免迁移,改为在 `FIELD_OVERRIDES` 扩展一个可选 `note` 字段并在 registry 写入时拼到 `field_name_cn` 前缀。**实施时确认 `_clean_comment` 与反射逻辑后,选择最小改动**:直接在 FIELD_OVERRIDES 加 `field_name_cn_override`(新 key)由 registry 优先采用,无则用反射值。

### 3. `docs/数据时间字段使用规范.md`(新建)— 持续性规范

内容:
- 客服上班时段定义(8:00~23:59 全年无休)与统计时段合规原则
- SYS/system 排除标准清单:`["sys","system","SYS","System"]`(必须 4 种全写,因 PG 大小写敏感)
- 时间字段优先级表(沿用审核报告第六节):
  | 场景 | 推荐 | 不推荐 |
  | 客服接待时段 | cs_records.operation_time | — |
  | 退费产生时间 | refunds.created_at_raw | ~~updated_at_raw~~ |
  | 工单产生时段 | service_tickets.register_time | ~~finish_time~~ |
  | 工单完成时间 | handle_duration + register_time | ~~finish_time~~ |
  | 用户提现 | wallet.op_time (op_type='用户提现') | — |
- `finish_time` 不可靠的证据(89% 非真实完成)与替代方案
- 上游 BMS 批量时间戳说明(03:15/02:05 是上游系统操作,凌晨合理,统计客服负荷时按 operator 排除)
- 已知不可靠字段清单(ticket.finish_time / refund_wide.ticket_finish_time / refund.updated_at_raw 已在 UI 隐藏)

### 4. `docs/规划设计.md` — 修订 sys/system 大小写表述

3 处把 `sys/system` 改为完整说明 `sys/system/SYS/System`(PG 大小写敏感,4 种写法均需排除),并补一句"详见 数据时间字段使用规范.md":
- L113:`operator` 为 `sys`/`system` → `sys`/`system`/`SYS`/`System`(4 种大小写写法,PostgreSQL 大小写敏感)
- L542:`sys/system` 标记为系统自动操作 → 同上
- L594:真实现金流出公式 `operator≠sys/system` → `operator NOT IN ('sys','system','SYS','System')`

## 验证方法

1. **重启后端让 seed 生效**:
   ```bash
   docker compose restart backend
   # 或 docker exec csctalon-backend python -c "from app.services.data_source_registry import ensure_data_sources_registered; from app.services.preset_views_seed import ensure_preset_views_registered; from app.core.database import SessionLocal; db=SessionLocal(); print(ensure_data_sources_registered(db)); print(ensure_preset_views_registered(db))"
   ```

2. **SQL 验证 case-fix 生效**(对比修改前后金额):
   ```sql
   -- preset_refund_trend 修改后应等于此查询(线上+排除4种sys/system)
   SELECT SUM(refund_amount) FROM refunds
   WHERE refund_method='线上' AND operator NOT IN ('sys','system','SYS','System');
   -- 对比:旧逻辑 NOT IN ('sys','system') 会多算 5577 条 SYS 退款
   SELECT SUM(refund_amount) FROM refunds
   WHERE refund_method='线上' AND operator NOT IN ('sys','system');
   ```

3. **UI 验证字段隐藏**:前端「数据查看 / 自助分析」维度选择里,`ticket.finish_time`、`refund_wide.ticket_finish_time`、`refund.updated_at_raw` 不再出现在筛选器/维度下拉。

4. **看板回归**:打开退款看板,确认 `preset_cash_trend_v2` / `preset_refund_operator_v2` / `preset_refund_daily_detail_v2` 数据下降(因排除了 5577 条 SYS);`preset_operator_ticket` 客服工单数下降(排除 SYS 6173 + 客户 283)。

5. **构建注意**:`docker compose build` 可能命中 COPY 层缓存导致代码不更新,需 `--no-cache` 强制重建(项目记忆已知坑)。
