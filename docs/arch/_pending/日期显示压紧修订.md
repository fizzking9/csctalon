# 日期显示压紧修订

## Context(为什么做这次修改)

当前分析视图的日期标签用完整 ISO 格式 `2026-08-01`(10 字符),在 30 天趋势图 X 轴、按日分组表格里高频重复,视觉冗余、信息密度低。管理页的「纯日期」字段(周报周期、措施日期等)同样冗长。

**目标**:按用户指定,把纯日期显示压紧为 `YY/MM/DD`(如 `26/08/01`),提升信息密度;带时分的时间戳(审计/操作日志)保留原样不动(精度需要)。

**用户已确认**:
- 范围 = 分析视图 + 管理页**纯日期**(不动带时分的时间戳)
- 格式 = `YY/MM/DD` 斜杠

## 安全性已验证(探索结论)

- 后端 `_apply_time_grain` 输出的日期串是**显示标签 + 排序键**,前端 ECharts 直接渲染,无 drill-down 把维度值回传当过滤值(已 grep 确认无 chartClick/drilldown)
- 时间范围过滤走独立 start/end 参数(ISO `YYYY-MM-DD`,来自日期选择器),**不**依赖维度串
- 无导出/下载端点重新格式化日期(routers 无 to_char)
- `YY/MM/DD` 带前导零 → **字典序 = 时间序**(沿用 `_apply_time_grain` 既有不变式),排序不受影响

## 修改清单

### 1. 后端: `backend/app/services/analysis_engine.py` 的 `_apply_time_grain`(L436-458)

把日期/月份/季度压紧,周与年保留(ISO 正确性 / 单独年份需 4 位):

| grain | 旧格式 | 新格式 | 示例 |
|---|---|---|---|
| day | `YYYY-MM-DD` | `YY/MM/DD` | `26/08/01` |
| month | `YYYY-MM` | `YY/MM` | `26/08` |
| quarter | `YYYY-"Q"Q` | `YY/"Q"Q` | `26/Q3` |
| week | `IYYY-IW` | `IYYY-IW`(保留,ISO 年正确性) | `2026-31` |
| year | `YYYY` | `YYYY`(保留,年份单独需 4 位) | `2026` |
| hour | `HH24` | `HH24`(保留) | `08` |

同步更新函数 docstring 的格式说明。

### 2. 前端: 4 个管理页的 `formatDate`(纯日期)压紧

把每个文件里**纯日期**的 dayjs 格式 `'YYYY-MM-DD'` → `'YY/MM/DD'`。**`formatTime`(带 HH:mm)保持不动**。

- `web/src/views/management/Measures.vue` L200:`formatDate` → `'YY/MM/DD'`(L201 `formatTime` 不动)
- `web/src/views/management/WeeklyList.vue` L109:`formatDate` → `'YY/MM/DD'`(L110 `formatTime` 不动)
- `web/src/views/management/ReportDetail.vue`:
  - L306 `formatDate` → `'YY/MM/DD'`
  - L309 `timeStartStr`、L310 `timeEndStr`(报告周期,纯日期显示)→ `'YY/MM/DD'`
  - L317 `formatTime` 不动
- `web/src/views/management/WeeklyDetail.vue`:
  - L301 `formatDate` → `'YY/MM/DD'`
  - L304 `weekStartStr`、L305 `weekEndStr`(周周期,纯日期显示)→ `'YY/MM/DD'`
  - L304/305 旁若有 `formatTime` 不动

### 3. 明确不动(避免过度修改)

- **带时分的时间戳**(`formatTime` = `YYYY-MM-DD HH:mm`、操作日志 `YYYY-MM-DD HH:mm:ss`)— 审计/操作日志需精度,保持原样
- `web/src/views/Dashboard.vue` L240 `YYYY年MM月DD日`(工作台顶部"今日"中文头) — 单条样式性标题,保留中文格式
- `web/src/views/data/Browser.vue` 数据浏览页的日期回退(L370) — 原始数据查看,保留完整值

## 验证方法

1. **后端**:`docker cp` 改后文件入容器或 `docker compose build backend && docker compose up -d backend`;打开任一按日趋势看板(如退款趋势),确认 X 轴显示 `26/08/01` 且**升序排列正确**(`26/08/01` < `26/08/02` < ... < `26/08/31`)。
2. **前端**:`docker compose build web && docker compose up -d web`(nginx 静态站需重建镜像);打开「周报列表」「措施列表」「报告详情」「周报详情」,确认周期/日期列显示 `26/08/01`,带时分的列(如更新时间)仍为 `2026-08-01 14:30`。
3. **回归点**:
   - 分析视图时间范围筛选仍可用(日期选择器仍发 ISO `YYYY-MM-DD` 给后端)
   - 按周/按月/按季度分组显示与排序正常(周保留 `2026-31`、月 `26/08`、季度 `26/Q3`)
   - SQL 验证排序不变:`SELECT to_char(now(),'YY/MM/DD')` → `26/08/01`
