## 〇、结论摘要（TL;DR）

1. **单日端点放开到分钟**：`date` 支持 `YYYY-MM-DD`（整天）**或** `YYYY-MM-DDTHH:MM`
   （该日 `00:00` ~ 该分钟）。动机：下游（workbuddy 等）需做**同刻日比对**
   （如 `09-10T12:30` vs `09-09T12:30`），整天粒度无法满足。
2. **响应增窗口元信息**：`window_kind` / `window_precision` / `window_start` /
   `window_end` / `compare_start` / `compare_end`（后两者 = 同比基准窗口）。
3. **`brief` 的 `start/end` 保持整天语义，显式拒绝分钟串**（跨度 `span_days` 计算
   会失真），不静默截断。
4. **AI 助手新增自然语言时间识别**，窗口判定优先级：
   `start/end` > `date` > **问句自然语言** > `period` 默认。
   识别结果通过 `window_source`/`window_label` **强制回显**给用户。
5. **防幻觉三原则**（本单新增约束）：识别结果必须回显；无把握一律退回 `period`
   默认（**不猜**）；不产生未来窗口。
6. **异步链路健壮化**：`analyze` 同步等待超时返回 `running` 时，前端必须轮询至终态，
   且抽屉关闭/刷新后续查（结果不丢）；失败 `error` 保证非空。

## 一、实证依据（2026-09-10 生产日志审计）

### 1.1 触发问题
用户反馈「AI 助手总是调用失败，还没啥提示」+「问两天运营数据对比，说没有数据」。

### 1.2 关键证据（nginx access.log + backend app.log）

| # | 证据 | 数值 |
|---|---|---|
| 1 | DeepSeek 调用状态 | **50 次全部 HTTP 200**，非 200 共 0；AI 任务 ERROR 0 条 |
| 2 | `POST /ai/analyze` 响应体分布 | 45 次中 **16 次 = 154 字节** |
| 3 | 用生产 `R(...).model_dump_json()` 标定 | 154 **唯一对应** `status=running`（6s 同步等待兜底）→ **越线率 36%** |
| 4 | `GET /ai/tasks/` | 仅 20 次（平均 **1.25 次/任务**），响应体**全部 350 字节** |
| 5 | 350 字节标定 | 唯一对应 `status=running`（`queued`=325 / `success(len0)`=372 / `failed`=399） |
| 6 | 端到端耗时 | `5.98s / 5.65s / 3.98s`，与 `AI_SYNC_WAIT_S=6.0` **几乎重合** |

**结论**：LLM 侧零故障，失败发生在**等待与传递的胶水层** —— 轮询从未拿到终态，
且前端 `pollTask()` 无 catch、答案仅存内存 + `el-drawer destroy-on-close`
→ 用户关抽屉即**静默丢失答案、零提示**。

### 1.3 「不够智能」根因
前端 `submit()` 只发 `{question, period}`，feed 永远取**当前窗口**；
`reception.total` 只有 `value/yoy_value/yoy_pct` → 模型手里没有「昨天」的独立明细
→ 只能答「昨日暂无数据」或拿 yoy 硬凑。

## 二、设计

### 2.1 只读平台：分钟级单日窗口

**入参（三个单日端点 `reception`/`refund`/`complaint`）**

| `date` 形态 | 窗口 | `window_kind` |
|---|---|---|
| 缺省 | 今日 `00:00` ~ now | `today_realtime` |
| `YYYY-MM-DD` | 该日整天 `00:00:00`~`23:59:59` | `full_day` |
| `YYYY-MM-DDTHH:MM` | 该日 `00:00` ~ 该分钟 | `minute_to_date` |

**护栏（全部 400，不静默降级）**

- 非法形态：带秒 / 缺分钟 / 非法时分 / 月日越界 / `20260910` / `2026-W01-1`
- 晚于当前北京时刻（防时间穿越）
- `brief` 的 `start/end` 遇分钟串 → 400（区间语义必须整天）

**同比基准（`compare_*`）**

- 整天 → 前一日整天
- 分钟 → 前一日**同刻**（`09-10T12:30` ↔ `09-09T12:30`），保证两个周期边界严格对齐

**缓存**

- 分钟窗口已终结（护栏保证不晚于当前时刻）→ 按日期感知 TTL（历史 24h / 今天 60s）
- key 含分钟段（`today:kpi:2026-09-10T12:30:None:None`），与纯日期 key 不冲突
- `_CACHE_DATE_RE` 必须容忍「日期+分钟」形态，否则分钟 key 会被当"无日期静态 key"
  在每次同步后全量删除，使长 TTL 形同虚设

**实现落点**

- `external._parse_window_arg_or_400()`（新）：统一解析 + 护栏
- `external._window_meta()`（新）：窗口元信息 + `compare_*`
- `analytics._resolve_windows()`：新增分钟分支（**纯日期路径逐行未变**）
- `analytics._parse_minute_end()`（新）：只认 16 位 `T` 串，纯日期返回 `None`

### 2.2 AI 助手：窗口判定优先级

```
start/end（显式区间）> date（显式单日）> 问句自然语言识别 > period 默认
```

**自然语言解析器**（`services/ai_time_parser.py`，新增）

| 类别 | 示例 |
|---|---|
| 相对单日 | 今天 / 昨天 / 前天 / 大前天 / `3天前` |
| 近 N 天 | 近3天 / 最近7天 / 过去5天 / 这10天 |
| 口语短区间 | 这两天 / 两三天 / 这几天 |
| 周 | 本周（周一~今天）/ 上周 / 上上周（完整自然周） |
| 月 | 本月（1日~今天）/ 上月（完整月） |
| 绝对日期 | `2026-09-10` / `2026年9月10日` / `9月10日` |
| 相对月+日 | 本月5日 / 上月20日 / **本月1日到5日**（终点省略月份） |
| 绝对区间 | 两个日期 → 覆盖两者的闭区间 |

**约束（设计原则）**

1. **只产出纯日期**（`YYYY-MM-DD`），与 `brief` 同粒度，不引入时分 → 避免与
   `_resolve_windows` 的"整天"语义分叉
2. **保守优先**：没把握 → `none`，退回 `period`；**绝不猜一个"看起来对"的窗口**
3. **必须回显**：`window_source` + `window_label` 随响应返回，前端渲染为窗口提示条
4. **不产生未来窗口**：晚于今天（北京）的日期直接丢弃，防空窗口被误读为"业务归零"
5. **优先级**：明确日期点 > 区间表达（如「本月1日到5日」取 1~5 日，不被「本月」扩到今天）
6. **掩码机制**：长规则先于短规则（`2026年8月15日` 不能被 `9月10日` 二次命中）

**跨天区间 → `period` 取 `weekly`**：仅为让 `refund_decision_overview` 的
`grain` 走 `week`（与 `brief` 的 range 同映射）；窗口本身由 `_window` 的 range
分支决定，`period` 在该模式下仅作展示标签。

### 2.3 异步链路健壮化

- **后端**：`_humanize_error()` 保证 `error` **非空**（生产曾出现 `error=None`
  → 前端只能显示"未知错误"）；且**不透出内部异常原文**（判据必须
  `isinstance(e, LLMError)`，**不可**用 `hasattr(e,'status_code')` ——
  `HTTPException`/`HTTPStatusError` 也带该属性，会泄漏内部表名/SQL 片段）
- **后端**：`analyze` 记 `build_ms` / `llm_ms` / `total_ms` / `window_source`；
  `running` 兜底响应带 `waited_s`
- **前端**：轮询**追到终态**；单次查询失败**重试**（上限 5 次）；超时/失败保留
  `task_id` 供**续查**；生成中显示已等待秒数；会话与待查任务落 `sessionStorage`
- **前端**：登出必须清理会话缓存（原 `localLogout` 只清 `localStorage`，会把上一
  账号的经营数据留给同一标签页的下一位使用者）

### 2.4 口径卡与铁律（防幻觉强化）

- `ai_glossary.timezone` 卡补「对比期语义」：`yoy_value/yoy_pct` 只覆盖**上一个等长
  周期**的汇总值，**不是另一天的独立明细**，不能当完整一天来陈述
- 含对比类词（对比/环比/昨天/上周/…）或**具体日期**的问句，**强制注入** `timezone` 卡
- System 铁律新增第 6/7 条：必须**写明统计窗口**；`yoy` 非独立明细

## 六、风险与取舍

1. **分钟窗口会增加缓存 key 维度** → 已确认 `_CACHE_DATE_RE` 容忍分钟形态；
   分钟窗口判定为"已终结"→ 可长缓存，不会因每次同步被清空
2. **`AI_SYNC_WAIT_S` 保持 6.0 未调整** —— 生产实测 `rt=5.1~6.3s`，越线率仍存在。
   本单选择「越线不丢结果」（轮询追终态 + 续查 + 进度可见），**而非调阈值**
   （调阈值只是把等待挪个位置）。若后续要降越线率，可选：
   降 `AI_MAX_TOKENS` / 冷路径 `_build_feed` 移入线程池（单 worker 下 1.2s 同步
   阻塞事件循环是真实隐患）/ 改纯轮询
3. **自然语言识别不可能 100% 准确** → 故强制回显 + 显式参数优先，让用户可纠错
4. **前端会话落 `sessionStorage`** → 已补登出清理；同源隔离 + DOMPurify 消毒
