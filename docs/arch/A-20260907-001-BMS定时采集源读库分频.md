## 一、目标与非目标

### 目标
1. 定时源集合从"代码常量推导"改为"读 DB default_sync=true AND enabled=true"，UI 开关当日生效、无需发版。
2. 建立高频/低频分频模型：高频 4 源沿用白天每小时 + 5:00/8:00 兜底；低频源每日固定 1 次，窗口最小化（前一天整天）。
3. 手动默认勾选/每日必达监控等既有语义边界不漂移；低频源纳入自愈闭环。

### 非目标
1. 不改手动同步默认勾选逻辑（fetch.py/miniapp.py 行为不变）。
2. 不做 frequency 列 schema 迁移（本期用"约定"分频；演进路径见 §二.2）。
3. 不把低频源纳入白天每小时增量或"每日必达监控"9 点首采判定。
4. 不解决"DB true 混入不适合抓取源"的准入问题——由低频档失败→缺口→告警闭环暴露。

## 二、分频模型设计

### 2.1 分频档位总览

| 档位 | 时刻 | 集合 | 窗口 | 熔断/失败语义 |
|---|---|---|---|---|
| 高频·白天增量 | 8~23,0 每小时（现状不变） | 高频集合（DB true ∩ 种子4源） | 当天 00:00~now | 专项熔断+单次重试（现状） |
| 高频·8:00 近7天全量 | 8:00（现状不变） | 高频集合 | 近7天 0点~now | 强制，失败记缺口 |
| 高频·5:00 前一天补跑 | 5:00（现状不变） | 有缺口→缺口清点；无缺口→高频集合前一天全量 | 前一天整天 | 强制 |
| **低频·每日固定档（新增）** | **LOW_FREQ_HOUR（默认 6:00，env 可配）** | 低频集合（DB true − 高频集合） | **前一天整天** | 强制；不写熔断；走缺口记账 |

> 不挂 5:00/8:00 的原因：5:00 被缺口逻辑劫持（有缺口只补缺口源，低频源无缺口会被跳过，无法保证每天固定）；8:00 近7天窗口对量大源过重。

### 2.2 高频 vs 低频集合

```
高频集合 = sync_source_configs default_sync=true AND enabled=true ∩ DEFAULT_SYNC_TYPES(种子4源)
低频集合 = sync_source_configs default_sync=true AND enabled=true − 高频集合
```

演进：未来把某源提为高频 → 在代码种子 BMS_DATA_SOURCES 标 default_sync=True（进 DEFAULT_SYNC_TYPES）即自动入高频+手动默认勾选+监控（三处同源）。若需更细覆盖 → 用 `options.sync_frequency`（JSONB）显式覆盖，本期不预建。

### 2.3 T+1 源（refund_record_report）退役特殊逻辑

- 低频档窗口=前一天整天，天然满足 T+1"次日抓前一天" → `T_PLUS_ONE_BMS_TYPES` 特殊逻辑可退役（删 bms_scheduler 常量与兜底追加分支，同步改 test_bms_scheduler_t1.py）。
- DB false 时不进任何定时档（退化为手动，与 A-20260905-001 D3 一致）。

### 2.4 低频源"每天固定 1 次"保证

1. 低频档独立分支，触发 = `now_cn.hour == LOW_FREQ_HOUR` 且未记账，**不看昨日缺口**，直接跑低频集合前一天整天。
2. 忙时顺延（不记账，下一分钟重试，6:00~6:59 窗口）；8:00 前未得闲→让位全量，当日空闲补跑；彻底未跑→告警+次日 5:00 缺口兜底。
3. 语义=强制兜底（force_all：忽略熔断、失败不写熔断）。低频不参与白天滑动窗口熔断/半开探测（次日固定档自然重试）。
4. 成功→缺口记账 full_day；失败→记 open 供次日清点。

## 八、风险清单

1. **首日冲击（高）**：低频档首日一次性跑 8 个从未定时跑过的大源，可能单源超时/限流/跨 8:00 挤压。→ 必须灰度。
2. **DB 开关污染（中，有先例）**：shanmao_refund 先例 → 凭证/登录态预检 + 失败进 gap + 告警；监控名单锁核心源。
3. **post-sync 钩子成本放大（中）**：8 低频源分 8 次提交=8 次全库扫描。→ 低频多源合并为一次 sync_all 提交（每天 1 次钩子）。
4. **名单漂移不自愈（中）**：半开/重试/gap/监控名单须收敛到 6.1 单一 helper。
5. **回滚路径**：改 DB default_sync=false 即停定时；或 LOW_FREQ_HOUR 置空禁低频档（无需发版）。

## 十、验收标准
1. UI 开/关 default_sync → 60s 内源进入/退出对应档位（/schedule/status 可见），无需重启。
2. /schedule/status 返回 high=4 核心源、low=其余 DB true 源。
3. 高频档回归：白天每小时照常，5:00/8:00 语义不变，熔断/半开/重试行为一致。
4. 低频档每天固定跑（无缺口也跑）；忙顺延；彻底未跑告警。
5. T+1 退役：refund_record_report DB true 时每天 6:00 抓前一天成功；DB false 不进任何定时。
6. 名单一致性：helper 被所有引用点一致调用；单测断言低频源失败→gap→次日 5:00 可补。
7. 边界不漂移：fetch.py/miniapp 手动勾选仍=4 核心源；data_arrival 名单未随 DB 变。
8. pytest/ruff 全绿（更新 test_bms_scheduler_t1.py）；审查无 CRITICAL。
