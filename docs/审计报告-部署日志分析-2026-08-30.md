## 一、严重问题（每次触发，功能静默失效）—— 2 个代码 Bug

### Bug 1：post-sync 钩子 `name 'Refund' is not defined`

- **日志**：`WARNING app.services.bms_sync: post-sync 钩子(关联匹配/宽表物化)失败,不影响同步结果: name 'Refund' is not defined`（出现 40+ 次，每次同步都报）
- **定位**：`backend/app/services/bms_sync.py` 第 704 行
  ```python
  total_refunds = hook_db.scalar(select(_func.count()).select_from(Refund)) or 0
  ```
  `Refund` 只在 `_collect_affected_from_imports` 内部（第 584 行）局部导入，外层 `_run_hook_once` 作用域不可见 → 每次执行到此处抛异常，被第 782 行吞掉。
- **影响**：关联匹配（match_all）能跑，但**退费宽表物化 + 增量刷新从未执行**。依赖宽表的看板（refund-recovery、人均效率等）聚合数据可能持续陈旧。
- **修复**（最小改动）：在 `_run_hook_once` 内、第 560 行 `from sqlalchemy import func as _func` 之后补一行：
  ```python
  from app.models.refund import Refund
  ```
  更规范做法：把第 584-589 行的模型导入整块上移到 `_run_hook_once` 顶部（嵌套函数经闭包仍可访问）。

### Bug 2：`name 'fix_unclosed_quote' is not defined`

- **日志**：`WARNING app.services.bms_fetcher: [refund] 日期范围裁剪/写回失败(保留原文件,不影响主流程): NameError: name 'fix_unclosed_quote' is not defined`（每次抓 refund 都报）
- **定位**：`backend/app/services/data_parser.py` 模块级函数 `repair_csv_blocks` 内，第 721 / 726 / 742 行调用：
  ```python
  line = fix_unclosed_quote(line)                 # L721
  fixed = fix_unclosed_quote_in_long_field(line)  # L726
  joined = fix_unclosed_quote(joined)             # L742
  ```
  这两个函数实际定义在**另一个函数内部**（第 321 行 `_fix_unclosed_quote`、第 380 行 `_fix_unclosed_quote_in_long_field`），带下划线前缀且作用域不可达 → NameError。
- **影响**：refund 导出 CSV 的"日期范围裁剪/写回"永远失效，每次都把**全量文件**直接入库（近 7 天全量 21158 行、单日 20901 行），增加解析/upsert 开销。
- **修复**：两函数为纯字符串工具、无闭包依赖，安全做法是**提升到模块级**并统一命名：
  1. 将第 321 行 `_fix_unclosed_quote`、第 380 行 `_fix_unclosed_quote_in_long_field` 两个 def 块整体移到模块级（可放在 `repair_csv_blocks` 之前），保持 `_` 前缀；
  2. 原函数内第 428 / 437 / 453 行调用已带 `_` 前缀，自动生效，无需改；
  3. 仅需修改 `repair_csv_blocks` 内 3 处调用：
  ```python
  line = _fix_unclosed_quote(line)
  fixed = _fix_unclosed_quote_in_long_field(line)
  joined = _fix_unclosed_quote(joined)
  ```
