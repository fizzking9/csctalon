# 审计报告-看板缓存优化（2026-08-31）

## 一、背景

生产环境审核发现：今日/运营看板**缓存有生效，但只覆盖「今日+本周」两个固定窗口**，叠加缓存 TTL 太短（60 秒），导致切换到其它历史日期时**永远冷查询（2~4 秒）**，来回切日期体验差。

## 二、根因分析（按影响排序）

| # | 问题 | 影响 |
|---|------|------|
| 1 | **前端无本地缓存**：`Today.vue` 每次切日期/切回同一天都 `Promise.all` 重拉 8 个接口 | 来回切历史日期每次冷查询（最高频动作） |
| 2 | **后端 TTL 太短（60s）**：历史数据本已定型不变，却被反复重算 | 冷查询反复发生 |
| 3 | **预热只覆盖 2 个固定窗口**（今日+本周），用户常看的历史日期永远冷 | 首次访问历史窗口冷查询 |
| 4 | **同步后全量失效** `today:*`/`refund:*`/`complaint:*`，历史缓存即使拉长 TTL 也被每小时清掉 | 历史缓存永远驻留不住 |
| 5 | **PG 未调优**（`shared_buffers=16MB`、`work_mem=4MB` 默认值） | 冷查询更慢 |

冷查询 2~4 秒的根源（重接口返回体量过大）：

- `today/refund-recovery`：一周数据返回 **2MB JSON**（2,029,343 字节）
- `complaints/detail`：一周 **513KB**
- `today/staff`：一周 **141KB**

## 三、修复方案与决策

采纳审核建议的 **A（日期感知 TTL）+ B（前端内存缓存）** 组合，并**增加第 3 项「近N天失效」**（审核建议未覆盖、但历史缓存驻留的前提）：

1. **日期感知 TTL**：历史窗口（`end < 今天`）TTL 拉长到 **24h**；含今天窗口保持 60~120s
2. **前端内存缓存**：`Today.vue` 按 `viewMode|start|end` 缓存上次结果，切回同窗口直接渲染、不发请求
3. **近 N 天失效**：同步/导入后失效从"全量前缀"改为"仅近 7 天窗口"，保留历史缓存长期驻留

**为什么安全**：同步完成后会失效「近 7 天窗口」缓存（数据一致性兜底不变），历史 24h TTL 不会造成数据陈旧——同步本身不涉及历史窗口数据。

## 四、改动清单

### 后端 `redis_client.py`（核心）

- 新增 `is_historical_window(start, end)`：`end` 严格早于今天 → 纯历史窗口
- 新增 `cache_ttl_for(start, end, base_ttl)`：历史窗口 → `HISTORY_TTL_SECONDS`(24h)，含今天 → 原 TTL
- 新增 `cache_invalidate_recent_days(prefix, recent_days=7)`：
  - 只失效 key 中日期落在「今天-N天 ~ 今天」的条目
  - 无日期片段的静态 key（`summary`/`op:status`）全部失效
  - 更早历史窗口保留
- `cached_json` 装饰器 `ttl` 参数支持 callable：`ttl=lambda **kw: cache_ttl_for(kw.get('start'), kw.get('end'), 60)`

### 后端路由层

- `analytics.py`：全部含 `start/end` 的 `cached_call`（30 处）改用 `cache_ttl_for`（today 系列、rw 全链路、refund 深度分析、op/cash/operator/reception）
- `complaints.py`：5 个窗口端点（summary/detail/backlog/subject/analysis）改用 lambda TTL
- `miniapp.py`：today:kpi/rr 无 start/end（实时今日视图），保持 60s 不变

### 后端同步失效点（5 处，全量→近N天）

| 文件 | 原 | 现 |
|------|----|----|
| `sync_task_manager.py` | `cache_invalidate_pattern("today:*")` 等 | `cache_invalidate_recent_days("today:*")` 等 |
| `bms_sync.py` | 同上 | 同上 |
| `complaint_sync.py` | 同上 | 同上 |
| `manual_refund_sync.py` | 同上 | 同上 |
| `uploads.py` | 同上 | 同上 |

> 管理员强制重建（`cache_admin.py` `rebuild_cache`）仍全量失效，属主动操作，未改。

### 前端 `Today.vue`

- 新增 `_viewCache`（单条，`key=viewMode|start|end`）：切回同窗口命中缓存直接渲染、不发请求
- 新增 `_forceRefresh()` = 日视图·今天；手动刷新按钮 + 60s 自动刷新 `loadAll({ force: true })` 强制重拉
- `onDateChange`/`onViewModeChange` 无参 `loadAll()`：切到新窗口 key 不同自然重拉，切回旧窗口命中缓存

## 六、部署注意

- 需**重新构建 web** + **重启 backend**（Redis 旧 key 无碍，新 TTL 在写入时生效）
- 历史缓存需**一次访问**才会以 24h TTL 写入；冷 key 首次仍会冷查询（2~4s）
- 监控：观察 `DBSIZE` 与历史 key 的 TTL（应出现 `ttl≈86400` 的历史窗口条目）
