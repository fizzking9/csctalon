# CSCTalon 项目审核报告：界面组织 / 办公流程 / 管理效果

> 版本：v0.6 审核 · 日期：2026-08-18
> 审核基线：origin/main `dde6d9d`（v0.5 全量功能 + 微信注册 + 移动端 H5）
> 审核依据：三套技能规范（.dsh/skills/）—— 界面组织 / 工作流设计 / 管理效果
> 结论：**功能层已完备（74 表 / 43 路由 / 65 页），薄弱点在「组织与效果」层：菜单结构、待办聚合完整性、报表价值治理。**

## 一、界面组织审核（依据 csctalon-ui-organization）

### 1.1 已做对的部分 ✅
- **角色化工作台**：`Dashboard.vue` 已实现 5 角色差异化首页（管理员/主管/专员/普通客服 + 专项组长），含待办/预警/异常快捷入口 —— 符合规范 §6。
- **状态色板工具** `web/src/utils/statusColor.js` 已建立统一语义色板 —— 符合 §4。
- **菜单按角色分层**：isManager/isAdmin 控制可见性 —— 符合 §3。

### 1.2 发现的问题 ❌（按严重度排序）

| # | 问题 | 违反规范 | 影响 |
|---|------|---------|------|
| U1 | **双"运营看板"入口**：`/dashboards/today`（title=今日看板，菜单标"运营看板"）+ `/dashboards/operation`（title=运营看板）；桌面/移动端入口不一致 | §3 菜单名与页面 title 一致 | 用户困惑，两个入口展示不同内容 |
| U2 | **一级菜单 13 项过散**：事项跟进/专项任务/设备专项标签/发票登记/知识库/报表中心 各自独立一级菜单，未按业务域归组 | §3 同业务域归组 | 侧边栏臃肿、导航成本高 |
| U3 | **数据分析能力入口错位**：视图构建器/视图清单/看板配置 在「系统管理」（admin-only），主管/专员无法消费分析视图 | §3 角色可见性 | 分析能力被锁死给管理员 |
| U4 | **报表中心是占位空壳**（194 行明确"规划中"）却挂在菜单 | §2 四范式 / 管理成本 | 僵尸入口 |
| U5 | 部分页面未完全按四层结构（页头/筛选/主体/页脚）组织，新老页面风格不一致 | §1 四层 | 观感不统一 |

### 1.3 界面优化方案（U 系列）

**U1 统一运营看板命名**：
- `/dashboards/today` → 菜单名改「今日看板」（与 title 一致）；`/dashboards/operation` → 菜单名「运营看板」，两者都保留，仅统一命名与入口位置（桌面/移动一致）。

**U2 菜单归组（一级菜单从 13 → 7）**：
```
工作台        (工作台 / 我的待办)
运营看板      (今日看板 / 运营看板)
决策看板      (管理层 8 子菜单)          ← 已有
数据与分析    (数据采集 / 分析视图 / 视图构建器·admin / 设备审计 / 人员审计)
运营工具      (设备专项标签 / 发票登记 / 知识库)
管理闭环      (报告 / 周报 / 措施 / 政策 / 异常 / 排班 / 预警 / 跨部门)  ← 已有
系统管理      (admin 8 项)              ← 已有
```

**U3 分析视图开放只读**：
- `/analytics/views` 从 admin → 全员可见（只读消费）；构建器/看板配置保留 admin。

**U4 报表中心下线**：菜单隐藏该占位页，待实现导出能力后再开放。

**U5 页面风格对齐**：新页面照四范式模板，老页面（Cash/Operation/RefundWithdrawal 等）渐进组件化（KpiCard/FilterBar/ChartCard）。

## 二、办公流程审核（依据 csctalon-workflow-design）

### 2.1 已做对的部分 ✅
- **统一待办中心** `/agenda` 汇聚待办/异常/措施/待读政策/待处理工单 —— 符合 §3。
- **通知中心** notifications + 角标，异常登记/政策发布有通知 —— 符合 §4。
- **状态机+时间线**：异常/措施/待办均带跟进时间线 —— 符合 §2。
- **发票流程**：提交→审核→报销→导出 Excel —— 闭环完整。
- **微信注册流程**：code 登录→提交资料→管理员审批→建号发 token —— 闭环完整。

### 2.2 发现的问题 ❌（按流程断点排序）

| # | 问题 | 违反规范 | 影响 |
|---|------|---------|------|
| W1 | **待办中心缺「待审发票报销」**：发票提交后进"待审核"，但未接入统一待办中心 | §3 待处理项必须进待办 | 主管需主动去发票页，违背"推着人走" |
| W2 | **微信注册审批未接入待办/通知**：新注册申请无站内信、不进待办中心 | §3+§4 | 管理员需主动查 pending 列表，审批可能积压 |
| W3 | **异常→转待办/转措施 一键联动 UI 缺失**：后端仅"转预期"，规划的"一键转待办/转措施"未落地 | §6 跨模块联动 | 异常处置动作要手工重建 |
| W4 | **预警默认无规则**：调度器已定时扫描，但规则表为空（部署后需手工配置） | §5 预警驱动 | 预警功能默认不生效 |

### 2.3 流程优化方案（W 系列）

**W1 发票待审接入待办中心**：`agenda.py` 增加 `reimbursements`（status=待审核）聚合，ref_type=reimbursement，一键跳转审核页。

**W2 微信注册接入通知+待办**：
- 新注册提交 → `notify` 所有管理员（type=registration）+ 进统一待办中心（新增"待审批注册"类目）。

**W3 异常一键联动**：
- 异常详情页加「转待办」「转措施」按钮（后端已有 todo/measure 创建能力，补前端入口 + 关联字段）。

**W4 预置预警种子规则**：启动种子注册 4 条默认规则（退款激增 100/工单积压 50/异常激增 20/投诉激增 30），可配置可停用。

## 三、管理效果审核（依据 csctalon-management-effectiveness）

### 3.1 已做对的部分 ✅
- **角色化工作台含例外入口**：主管首页有待办/预警/异常高亮 —— 符合 §1 例外管理。
- **预警驱动**：调度器定时扫描 + 幂等 —— 符合 §5。
- **周报一键生成** + 10 项框架自动填充 —— 符合 §4。
- **绩效看板**（汇总不扣分）、归因不归责已文档化 —— 符合 §2/§6。

### 3.2 发现的问题 ❌

| # | 问题 | 违反规范 | 影响 |
|---|------|---------|------|
| M1 | **报表价值未治理**：analytics 4 分析页（运营/现金流/退款分类/人员操作）与决策看板（退款/投诉/接待/绩效）功能重叠，未按"谁看/看完做什么决策"审计 | §3 砍掉没人看的报表 | 冗余报表分散注意力 |
| M2 | **报表中心占位入口**（同 U4）：管理层菜单里一个"规划中"空壳 | §3 | 僵尸入口 |
| M3 | **措施到期回看缺少"超期醒目"**：measures 到期进待办，但超期未标红/升级 | §1 例外管理 | 超期措施可能被忽略 |

### 3.3 管理效果优化方案（M 系列）

**M1 报表价值审计**：
- 运营分析/现金流分析/退款分类/人员操作 4 页 → 建议与决策看板合并或保留差异化视角（如"运营分析=管理层日常"、"现金流分析=财务对账"各留一份），标注每页的"谁看/决策"，删并无主页面。
- 建议把 4 个 analytics 分析页并入「数据与分析」菜单，决策看板保持 8 个专项。

**M2 报表中心下线**：同 U4，菜单隐藏。

**M3 措施超期标红**：`agenda` 的 measures 项，verify_time 已过且 status=executing → 标记"已超期"（红色），主管首页优先展示。

## 五、结论

- **功能完备度**：v0.5 规划功能 + 微信注册 + 移动端全部落地，运行验证通过（冒烟 18/18、深测 10/10）。
- **最该补的三件事**（投入小、见效快）：
  1. **待办中心补全**（发票待审 + 微信注册审批）—— 让"推着人走"真正闭环；
  2. **菜单归组 + 命名统一 + 下线占位页** —— 让界面组织符合管理直觉；
  3. **预置预警规则 + 措施超期标红** —— 让管理效果立竿见影。
- 三套技能规范已加载为项目技能（`.dsh/skills/`），后续开发/评审可随时调用。
