## 五、端到端验证步骤（待执行）

1. 建临时分支，加一行代码改动（非 docs），commit。
2. 发 PR，标题**不含**工单号 → 预期 G1 红（拦截）。
3. 改 PR 标题加 `#1` → 预期 G1 绿，且 G2 回写评论到工单 #1。
4. 合并该 PR → 预期 G3 对 #1（incident）**仅评论不关闭**。
5. 再测一条 `governance` 单（如 #2）：合并后应自动 Closed。

> 说明：`test.yml` 的 G2 回写与 `issue-close-on-merge` 的 G3 均只在 `pull_request` 事件下触发，push 不触发（符合设计）。

## 六、已知边界（验证时需注意）

- G1 的 PR files 查询若失败会得到空列表，当前逻辑按“有代码变更”处理（宁可拦截不漏放）。
