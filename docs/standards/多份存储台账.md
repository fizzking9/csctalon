# 多份存储台账（同事实多处存储登记）

**性质**：参考（REF）—— 现状台账，无约束力；口径以代码与相关 META 规范为准。

> 来源：工单 #278（排期 O-7 / S-P2-3）。
> 目的：把「同一业务事实被存了多份」的位置集中登记，每处注明 **真身/投影、
> 同步机制、一致性风险、收敛计划**，防止「改一处不影响另一处」式漂移。
> 维护纪律：**新增多份存储时必须登记于此**；收敛完成后划销（保留历史行 + 标注完成日期）。
> 与 O-1(#274) 联动：O-1 输出收敛项，本台账负责登记口径。

## 六、明确排除（不属于多份存储）

- **SCD Type 2 历史表**（`staff_assignment` 等）：同表历史化，非跨表重复。
- **`persons` / `person_aliases` / `scrm_staff_profiles`**：身份归一体系（别名→真身映射），是「一处真身 + 映射表」而非多份存储。
- **各表 `quality_status` 治理标记**：同表列，非跨表重复。
- **Redis 缓存**：派生缓存受《数据源接入与缓存加速规范》约束，不属于存储重复。
