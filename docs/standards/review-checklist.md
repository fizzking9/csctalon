# 代码审查清单（30-reviewer）

**性质**：元需求（META）—— 提供**所有**代码审查的判据（CRITICAL 阻塞合并）
**生效日期**：2026-09-01
**适用范围**：所有 AI 初审 / 人工终审
**关联文档**：AGENTS.md（全局约束）、[error-code.md](error-code.md)、[数据时间字段使用规范.md](数据时间字段使用规范.md)、[界面设计说明规范.md](界面设计说明规范.md)、[看板卡片数据说明与下钻规范.md](看板卡片数据说明与下钻规范.md)、[文档性质标记规范.md](文档性质标记规范.md)

> 审查流程：AI 初审（逐项核对本清单）→ 输出分级报告 → 人工终审（业务正确性 + 边界 + 兼容性）。
> AI 初审**只输出报告，不修改代码**；有 CRITICAL 则切回 Developer 阶段修复后重审。

## 一、AI 初审检查清单（必须逐项核对）

### 文档性质（新增/改动约束性文档时必查）

> 依据：`docs/standards/文档性质标记规范.md`。区分「需求」与「需求的需求」。

- [ ] 新增/改动的约束性文档，头部含 `**性质**：元需求（META）/ 需求（REQ）/ 参考（REF）`
- [ ] 已在 `docs/README.md` §六「文档性质索引」登记
- [ ] 若为 **META 且含强制条款** → 已挂进 `AGENTS.md` 引用链（否则标记≠约束）
- [ ] 若为 **REQ** → 有功能边界 + 接口契约 + 验收标准 + 归属工单
- [ ] 若为 **REF** → 已声明「以代码为准」，不当作约束引用
- [ ] 性质判定用的是「**约束范围**」而非文件名（名为"XX接入规范"但只约束单个集成的 → REQ）

### 安全

- [ ] SQL 注入风险（是否全部参数化 / `text()` 绑定参数，无字符串拼接）
- [ ] XSS 风险（前端输出是否转义；后端返回的富文本 / HTML 是否安全）
- [ ] 硬编码敏感信息（密码 / 密钥 / Token / 内网 IP / 数据库账号）
- [ ] **库名与运行模式是否自洽**（`APP_MODE=dev`→库名 `*_dev` / `test`→`*_test` /
      `prod`→不含 `_dev`/`_test`）；**新增的库名默认值是否指向真实库**
      （这是"硬编码连接信息"的等价风险，见 `docs/arch/A-20260922-001`）
- [ ] **破坏性 DB 操作是否过守卫**：`DELETE`/`TRUNCATE`/`DROP`/批量 `UPDATE`
      是否先调 `app.core.db_guard.assert_safe_to_destroy()`；
      操作真实库是否**显式**授权（`allow_real_db=True` / `--allow-real-db`），
      而非用环境变量隐式放行
- [ ] **新增 `scripts/**` 是否经 `scripts/_bootstrap.py`** 进入
      （禁止自己拼 `POSTGRES_DB` 环境变量 —— 两份定义必漏，见 A-20260910-004 漂移教训）
- [ ] 静态文件 / 上传路径是否有路径穿越与 dotfile 暴露风险

### 正确性

- [ ] 空指针 / 越界访问（`None` 解引用、空列表索引）
- [ ] 资源泄漏（DB 连接、文件句柄、Redis 连接是否关闭）
- [ ] 事务回滚逻辑（多步写操作是否包在事务里，异常是否回滚）
- [ ] 金额是否为整数（分），无浮点精度隐患
- [ ] 时间字段是否遵守 `docs/standards/数据时间字段使用规范.md`（`Asia/Shanghai` 时区、`SYS/system` 排除）
- [ ] **禁止对 ORM 列使用 `X.col is True/False`**（`InstrumentedAttribute is True` 恒为 False → `.where()` 恒假 → 查询静默返回空，见 `#4` 事故）；布尔列必须用 `X.col.is_(True/False)` 或 `== True/False`；`is True/False` 仅可用于普通 Python 变量

### 一致性

- [ ] 与架构文档一致（是否擅自改接口路径 / 返回字段）
- [ ] 响应格式符合 `docs/standards/error-code.md`（成功 `{code:0,data,message}`，错误走 HTTPException）
- [ ] 接口路径是否在 `docs/API接口文档.md` 中登记或同步更新
- [ ] 表结构变更是否走 Alembic migration
- [ ] **前端 TS 渐进约定（#282 / O-12，2026-10-09 起）**：`web/src/` 下**新增**文件一律 `.ts`（既有 `.js` 不追溯、不强制改写）；新增 `.js` 须在 PR 描述中说明理由（如第三方脚手架产物）

### 性能

- [ ] N+1 查询（循环内查库 / 循环内调接口）
- [ ] 大数据量是否分页 / 加索引 / 批量查询
- [ ] 缓存使用是否合理（Redis key 设计、失效策略）

### 界面设计说明（前端改动必查）

> 依据：`docs/standards/界面设计说明规范.md`。**未提供设计说明的前端界面改动，直接判 CRITICAL。**

- [ ] 代码层：界面文件头部含 `设计说明（Design Rationale）` 注释块，且**五要素齐全**
      （目的 / 逻辑 / 口径 / **取舍** / 工单）
- [ ] 页面层：使用者可见的 ⓘ 气泡 或「设计说明」抽屉存在，**含「取舍」段**（不做什么及原因）
- [ ] 口径出处：设计说明中的口径标注了 `docs/standards/` 对应文档
- [ ] 无意图改动：无「顺手加图」「多堆 tab」；**每个图表都能指向一个动作**
- [ ] 可控指标前置：不是只堆后果指标（总量 / 金额）
- [ ] 重复展示：同指标若与其它页面重复，已声明「真身 / 投影」关系
- [ ] 关联工单：设计说明含 issue 号与设计文档路径

### 看板卡片数据说明与下钻（含 `dashboards/` 的改动必查）

> 依据：`docs/standards/看板卡片数据说明与下钻规范.md`。
> **看板卡片缺数据说明或缺下钻 → 判 CRITICAL。**

- [ ] 卡片有 ⓘ 说明，且含**来源 / 口径 / 时点**三要素
- [ ] 说明写的是**判据**而非形容词（不写「展示分布」，写「按 X 分类、排除 Y」）
- [ ] 若卡片可为空，说明中写明**什么情况下为空**（区分业务为空 vs 功能故障）
- [ ] 卡片**可下钻**，且下钻**带时间窗口 + 筛选条件**（禁止落到默认窗口让用户重筛）
- [ ] 无法带全上下文时，代码注释写明**为什么**
- [ ] 若**不可下钻**，代码注释 + 页面 ⓘ 均声明**理由**（禁止沉默）
- [ ] 可点击元素有 `cursor: pointer` 与 hover 反馈
- [ ] 说明文案中的动态值（阈值 / 窗口）**从数据读取**，不硬编码

### 看板技术路线主序（新增看板 / 手写看板页必查）

> 依据：`docs/standards/看板卡片数据说明与下钻规范.md` §八（#259）。

- [ ] 新增看板默认走**配置驱动**（Designer + DashboardView + ViewItemCard）；走手写大页须在设计说明写明属于哪类例外（复杂交互 / 存量改造）
- [ ] 手写页 KPI / 卡壳 / 筛选元素**复用** `components/dashboard/` 标准封装（KpiCard/ChartCard/FilterBar 等），禁止内联重写；新封装优先沉淀到该目录

## 二、AI 初审输出格式

```markdown
## 审查报告
- 审查对象：<文件路径>
- 审查依据：docs/standards/review-checklist.md

### 严重（CRITICAL）
- [ ] 无
- [ ] 第 XX 行：<描述，必须修复，阻塞合并>

### 警告（WARNING）
- [ ] 第 XX 行：<描述，建议修复，非阻塞>

### 信息（INFO）
- [ ] 第 XX 行：<描述，风格建议>

### 与架构一致性
- [ ] 接口路径与 docs/arch/ 对应文档一致
- [ ] 返回字段与接口契约一致
```

分级规则：

| 级别 | 含义 | 处理 |
|---|---|---|
| CRITICAL | 必须修复 | 阻塞合并，切回 Developer 修复 |
| WARNING | 建议修复 | 非阻塞，可后续处理 |
| INFO | 风格建议 | 仅供优化参考 |

## 三、人工终审重点（AI 容易漏）

1. **业务逻辑正确性**：对照需求卡 / 派工单逐条核对（不只核对代码本身）
2. **边界条件完整性**：`page=0`、`page_size=999`、空列表、超长字符串、`None` 输入
3. **与现有系统兼容性**：是否引用了最新版本的内部库 / 是否影响既有同步任务、宽表、历史数据
4. **数据同步口径**：新增字段是否影响 SCD Type 2 历史表、`wide_table_builder`、预设视图
