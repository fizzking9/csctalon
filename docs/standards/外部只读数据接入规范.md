# 外部只读数据接入规范

> 版本：v1.1 · 2026-09-07（v1.0 2026-09-02）
> 适用：workbuddy 等外部工具**拉取**本系统经营数据（接待/退款/投诉/简报），自行组合生成报告。
> 配套：数据**推送**类接入（投诉/手动退款）见 `workbuddy数据同步接入规范.md` / `workbuddy手动退款数据同步接入规范.md`，本规范只覆盖**只读拉取**。
>
> **v1.1 变更（2026-09-07）**：① `brief` 新增可选 `start/end` 任意区间参数（历史标准周回看 = 传周一~周日），`period` 模式向后兼容不变；② 限频 `rate_limit_per_min` 支持 `0=不限制`（`0` / 空=全局默认 / `>0`=个性化 三值）。

---

## 1. 背景与目的

系统对外开放一组**带 scope 授权的只读 API**，外部工具凭 token 按需拉取经营数据：

- 三核心单日维度：接待 / 退款 / 投诉（`date` 缺省=今天，可回看历史某天）
- 一键经营简报：`brief`（`period=daily/weekly/monthly`），一次返回接待专项/退款(四路+涉诉率)/投诉(三源×登记/处理/积压)

**本规范不包含**数据推送（那是另一类接入）。token 由系统管理员在「系统管理 → 外部接入」生成并分发，每个 token 绑定权限范围（scope）与限频。

---

## 2. 接入总览

| 项目 | 值 |
|---|---|
| 接口前缀 | `{BASE_URL}/api/v1/external` |
| 鉴权方式 | HTTP 请求头 `Authorization: Bearer <token>` |
| token 获取 | 联系系统管理员在「系统管理 → 外部接入」生成；明文**仅生成时显示一次**，请立即保存 |
| 权限范围(scope) | `reception`(接待) / `refund`(退款) / `complaint`(投诉) / `brief`(经营简报)；token 只返回其 scope 允许的数据 |
| 数据格式 | `application/json`，成功统一 `{code:0, data, message:"ok"}` |
| 金额单位 | **元**（2 位小数）；不做分/元换算 |
| 时间 | 统一北京时间（`Asia/Shanghai`） |
| 限频 | 每 token 限频三值：`0`=不限制 / 空=全局默认 / `>0`=每分钟次数（管理员配置）；超限返回 `429` |
| 只读 | 所有端点只读，不会写入或修改业务数据 |

`BASE_URL` 为系统对外访问地址（如 `https://csctalon.example.com`），由系统管理员提供。

---

## 3. 鉴权

```
Authorization: Bearer <token>
```

- 未配置/未启用（服务端 `EXTERNAL_API_ENABLED=false`）→ `503`
- token 无效 / 已吊销 / 已过期 → `401`
- token 无该接口所需 scope → `403`
- 触发频率限制 → `429`

## 4. 只读端点

### 4.1 当日/指定日接待量 — scope: `reception`

```
GET /api/v1/external/reception?date=2026-09-01
```

- `date` 可选，`YYYY-MM-DD`，缺省=今天（北京时间）。历史日期返回整天；今天返回截至当前的实时累计。
- 响应 `data`：
  ```json
  {
    "date": "2026-09-01",
    "generated_at": "2026-09-01T18:30:00+08:00",
    "reception": {
      "value": 123, "yoy_value": 110, "yoy_pct": 11.8,
      "device_count": 88, "device_count_yoy": 80
    },
    "_spec": { "reception": "接待量=客服处理记录数(cs_record.operation_time 落当日); device_count=去重设备SN数" }
  }
  ```
- `value` 接待量、`yoy_*` 与昨日同时间区间比较、`device_count` 当日服务的独立设备数。

### 4.2 当日/指定日退款 — scope: `refund`

```
GET /api/v1/external/refund?date=2026-09-01
```

- 响应 `data`：
  ```json
  {
    "date": "2026-09-01",
    "refund_count":  { "value": 12, "yoy_value": 10, "yoy_pct": 20.0 },
    "refund_amount": { "value": 3560.50, "yoy_value": 2800.00, "yoy_pct": 27.2 },
    "refund_done_today": { "value": 8, "amount": 2200.00 },
    "actual_cashflow": { "value": 3000.00, "yoy_value": 2500.00, "yoy_pct": 20.0 },
    "_spec": { "...": "口径说明..." }
  }
  ```
- `refund_count/refund_amount` = 四路经营合计（A线上直退 + B钱包取现 + C闪猫 + D手动，按创建时间），金额单位=**元**。
- `refund_done_today` = 路线A 中当日实际完成退款（按更新时间）。
- `actual_cashflow` = 真实现金流 E（refund_record_reports 退款成功合计，对账基准；2026-09-05 v1.1 起替代 merchant_refunds 快照）。

### 4.3 当日/指定日投诉 — scope: `complaint`

```
GET /api/v1/external/complaint?date=2026-09-01
```

- 响应 `data.complaint.value` = 投诉量（service_tickets 投诉 + external_complaints + card_complaints 三表并集，落当日），含 `yoy_*`。

### 4.4 一键经营简报 — scope: `brief`

```
GET /api/v1/external/brief?period=daily
GET /api/v1/external/brief?period=weekly
GET /api/v1/external/brief?period=monthly
GET /api/v1/external/brief?period=daily&date=2026-09-01   # 回看某整天

# v1.1: start/end 任意区间(历史标准周/指定整天/任意连续区间) —— 与 period 互斥, 同时给出则优先
GET /api/v1/external/brief?start=2026-08-03&end=2026-08-09   # 历史标准周(ISO 自然周 周一~周日)
GET /api/v1/external/brief?start=2026-09-01&end=2026-09-01   # 指定整天(等价 period=daily&date)
GET /api/v1/external/brief?start=2026-08-01&end=2026-08-31   # 任意连续区间
```

**period 窗口口径（v1.0 不变）：**

| period | 窗口 |
|---|---|
| `daily` | 当日 0 点起（实时）；带 `date` → 该整天 |
| `weekly` | 整周核算（周一起） |
| `monthly` | 整月核算；当月未满月则 1 日至当前 |

**`start/end` 任意区间（v1.1 新增）：**

| 用法 | 语义 |
|---|---|
| `start`/`end` 同时给出 | 走任意区间（优先于 `period`/`date`）；`end=今天` → 实时截止 now；否则整天 |
| 只给一个 / 起>止 / 非法日期 | `400` |
| `end` 晚于今天（未来日期） | `400`（防时间穿越） |
| 跨度超过上限 | `400`（默认 **93 天 ≈ 1 季度**，服务端可配 `EXTERNAL_BRIEF_MAX_RANGE_DAYS`） |
| 响应 | 增加 `range: {start, end, span_days}` 字段；`period` 返回 `"range"` |

**参数精度与时间边界：**
- `start`/`end` **只接受纯日期 `YYYY-MM-DD`**；传带时分秒（如 `T09:00:00` 或含空格）→ `400`。
- **跨天区间**（`start`≠`end`，历史）：默认整天 —— `start` 日 `00:00:00` 起、`end` 日 `23:59:59` 止（北京时间）。
- **`end=今天`**（含单日=今天）：实时截止当前时刻 `now`（非 23:59:59），与 `period=daily` 当日口径一致。
- **历史单日**（`start=end` 且非今天）：该整天。

> 例：`start=2026-08-03&end=2026-08-09`（历史周）= `2026-08-03 00:00:00 ~ 2026-08-09 23:59:59`；
> `start=2026-09-07&end=2026-09-07`（今天）= `2026-09-07 00:00:00 ~ now`。

> ⚠️ 历史标准周 = **ISO 自然周**（周一为一周起点，与系统周报口径一致）。回看某周请自行换算该周**周一~周日**作为 `start/end`；服务端按闭区间原样解释，不做周号解析。
>
> ⚠️ **单次宽度护栏**：`start/end` 区间有跨度上限（默认 93 天），且 `end` 不能晚于今天——这是与限频（每分钟调用次数）**正交**的另一层保护，防止一次拉太宽历史窗口压库或把只读接口当全量导出工具。需要拉更长历史请**分多段**（每段 ≤ 93 天）调用。

**响应 `data` 结构（概览）：**

```json
{
  "period": "daily",
  "date_start": "2026-09-01T00:00:00+08:00",
  "date_end": "2026-09-02T18:30:00+08:00",
  "generated_at": "...",
  "reception": {
    "total": { "value": ..., "yoy_pct": ... },
    "by_specialty": [
      {
        "specialty": "退款挽回",
        "lead": { "name": "...", "role": "lead" },
        "members": [ { "name": "...", "position": "...", "group_name": "...", "is_primary": true, "workload_ratio": 1.0 } ],
        "sessions": { "value": 42 },
        "devices": { "value": 30 }
      }
    ]
  },
  "refund": {
    "total_amount": { "value": ... },
    "total_count": { "value": ... },
    "routes": {
      "route_a": { "count": ..., "amount": ... },   // A线上直退
      "route_b": { "count": ..., "amount": ... },   // B钱包取现
      "route_c": { "count": ..., "amount": ... },   // C闪猫
      "route_d": { "count": ..., "amount": ... }    // D手动
    },
    "actual_cashflow_e": { "count": ..., "amount": ... },
    "a_route": {
      "litigation_ratio": { "value": 12.5, "yoy_pct": null },
      "litigation_amount": 860.00
    }
  },
  "complaint": {
    "total": { "registered": ..., "handled": ..., "backlog": ... },
    "by_source": [
      { "source": "内部投诉",   "registered": ..., "handled": ..., "backlog": ... },
      { "source": "商户号投诉", "registered": ..., "handled": ..., "backlog": ... },
      { "source": "外部投诉",   "registered": ..., "handled": ..., "backlog": ... }
    ]
  },
  "_spec": { "口径注释": "..." }
}
```

**字段口径要点：**

| 字段 | 口径 |
|---|---|
| `reception.by_specialty` | 系统正式专项（咨询接待/套餐专项/退款处理/退款挽回/内部投诉/外部投诉）；`members`=该专项当前分配人员（组织口径）；`sessions/devices`=本专项成员当期接待会话/设备数 |
| `refund.routes` | 四路经营分别金额，单位=元 |
| `refund.a_route.litigation_ratio` | **A路直退涉诉率（%）** = 涉诉金额 / A路(线上直退)金额 ×100；涉诉=SN 关联投诉工单(外部>商户号>内部) OR 备注含投诉标识（涉投诉/客诉/投诉/315/争议/催退）；**清退/计划退款不算涉诉** |
| `complaint.*.registered` | 窗口内新登记投诉数 |
| `complaint.*.handled` | 窗口内完成/办结投诉数（有效 finish_time 落窗口） |
| `complaint.*.backlog` | 当前未闭环存量（归一化状态非已完成） |
| `complaint` 三源 | 内部(工单商品/服务投诉) / 商户号(微信投诉) / 外部(外部平台+315+卡商，并入外部桶) |

## 5. 错误码

| 状态码 | 含义 |
|---|---|
| 200 | 成功 |
| 400 | 参数错误（date 非法等） |
| 401 | token 无效 / 吊销 / 过期 |
| 403 | token 无该接口 scope |
| 429 | 频率限制（每 token 每分钟次数超限） |
| 503 | 外部只读接口未启用（服务端 `EXTERNAL_API_ENABLED=false`） |

错误响应体：`{ "detail": "错误描述", "code": "ERROR_CODE" }`。

## 6. 调用示例（curl）

```bash
# 生成 token 后(管理员在系统内生成并分发), 携带 Authorization 调用:

# 今日接待
curl -H "Authorization: Bearer <token>" \
  "{BASE_URL}/api/v1/external/reception"

# 今日简报(daily)
curl -H "Authorization: Bearer <token>" \
  "{BASE_URL}/api/v1/external/brief?period=daily"

# 本周简报(weekly)
curl -H "Authorization: Bearer <token>" \
  "{BASE_URL}/api/v1/external/brief?period=weekly"

# v1.1: 历史某标准周简报(ISO 自然周 周一~周日)
curl -H "Authorization: Bearer <token>" \
  "{BASE_URL}/api/v1/external/brief?start=2026-08-03&end=2026-08-09"
```

> workbuddy 每半小时拉一次建议用 `brief?period=daily`（今日累计），由调用方按 `_spec` 口径自行排版成简报文字。
> 高频实时拉取可让管理员把该 token 限频设为 `0`（不限制）——**仅限受信任调用方**，管理界面有 `last_used_at` 可观测。
