### C-P1-7 收尾与同类排查（2026-09-20）

**① 止损与治理（#160 / #161）**
- #160：删除 `wallet_withdrawals` 中 `device_sn IS NULL` 的重复行 **40603 行**（69455→28852），
  备份 = 表 `wallet_withdrawals_bak_20260919` + `pg_dump` `/opt/csctalon/backups/wallet_withdrawals_20260919.sql.gz`（2.5M）
- #161：迁移 `h3i4j5k6l7m8` 建**部分唯一索引**
  `uq_wallet_withdrawals_null_sn (account_id,op_type,op_time,operator,op_amount) NULLS NOT DISTINCT WHERE device_sn IS NULL`；
  `upsert_wallet` 按 `device_sn` 是否为空分流两个冲突目标；生产 `git-20260919233401`

**② 同类风险全库排查（2026-09-20，只读）**
- 范围：生产库 public schema **59 个唯一索引**（非主键），其中含可空列 **19 个**
- 结论：**生产无保护缺口**（wallet 已由 #161 治理）
- 判据（两轮修正，最终版见脚本文件头「两条铁律」）：
  1. **复现索引真实语义**：列清单取 `pg_get_indexdef` 括号内原文（含 `date(x)`/`COALESCE`），
     部分索引带 `WHERE indpred`。仅用 `indkey` 裸列名分组会误报
     （曾致 `manual_refunds` 报「3062 行重复」等 5 处全误报）
  2. **重复 = NULL 视为相等（`GROUP BY` 语义），但要再分「整组全 NULL」与「部分列有值」**：
     - **整组全 NULL**（`ai_reports.task_id` 176 行全 NULL、`dashboards.code` 2 行全 NULL）
       → **设计如此**，排除（该行在索引语义下无信息）
     - **部分列有值、仅某列 NULL**（`wallet_withdrawals`：仅 `device_sn` NULL）
       → ⚠️ **真缺口**（非 NULL 列足以判定「同一笔」，索引却拦不住）—— 这正是 C-P1-7 本质
     - 生产实测：4 处报警全为「整组全 NULL」→ 排除；wallet 治理后归零
- 已防护项：`cs_records.uq_cs_record_business`（NND）、
  `wallet_withdrawals.uq_wallet_withdrawals_null_sn`（部分 + NND）
- ⚠️ **本项首版判据有误**：曾把「组内全为 NULL」一律当豁免 → 会在**未治理环境**（如本地开发库）
  把 wallet 的 15601 行真重复静默跳过。已在脚本铁律 ② 修正，并用本地库反证
  （修正后本地库精确报出 wallet 为唯一缺口，生产库归零 —— 同一脚本两种环境结论正确区分）
- 脚本已入库：`scripts/governance_scan_unique_dup.py`（`scan` 扫描 / `--triage` 甄别），
  可直接作为治理框架 D1 探测器 v1 原型
