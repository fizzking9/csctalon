四、改进建议优先级

P0 — 立即行动

P0
建立测试体系
现状: tests/ 目录完全为空，pytest 已在 dev 依赖中但无用例。
建议: 至少为核心模块编写测试：认证流程（登录/登出/改密）、analytics 关键计算逻辑、数据同步 upsert 逻辑。使用 pytest + httpx AsyncClient 做集成测试，目标覆盖核心路径 60%+。

P1 — 短期改进（1-2 周）

P1
拆分超大文件
analytics.py（8508 行）按业务域拆分为 analytics/refund.py、analytics/complaint.py、analytics/reception.py 等；bms_fetcher.py（3273 行）按功能拆分为 fetcher/、parser/、auth/ 等。目标单文件不超过 800 行。
P1
清理裸 except 异常处理
30+ 处 except Exception: 静默吞错。至少应加 logger.warning() 或 logger.debug() 记录被吞掉的异常，避免出现"功能不工作但日志里什么都没有"的排查惨案。
P1
清理死依赖
从 pyproject.toml 和 Dockerfile 中移除 passlib[bcrypt]（代码已直接使用 bcrypt 库）。Dockerfile 内联 pip install 改为 pip install -e . 统一从 pyproject.toml 安装，消除双重维护。

P2 — 中期改进（1 个月内）

P2
引入 TypeScript
逐步将前端 .vue/.js 迁移到 TypeScript，优先改造 API 层和 store 层，利用 Vue 3 + Vite 的 TS 原生支持。
P2
添加 ESLint + Prettier
前端缺少代码规范工具，建议配置 eslint-plugin-vue + @typescript-eslint + prettier。
P2
建立 CI/CD 流水线
配置 Gitea Actions 或 GitHub Actions：lint → test → build → docker push，每次 PR 自动检查。
P2
限速迁移至 Redis
将登录限速从进程内内存改为 Redis 实现，为未来多 worker 扩展做准备。代码注释中已标注此为 M5 待办。

P3 — 长期优化

P3
CONFIG_ENCRYPTION_KEY 独立化
生产环境显式设置独立 CONFIG_ENCRYPTION_KEY，解除与 JWT_SECRET_KEY 的派生耦合。.env.example 中已提示但默认留空。
P3
前端大组件拆分
SyncDashboard.vue（2010 行）和 Today.vue（1816 行）按功能区域拆分为子组件，提高复用性和可维护性。
P3
依赖版本精确锁定
后端 pyproject.toml 使用 == 精确锁定版本或生成 requirements.lock，确保构建可复现。

五、审计结论

CSCTalon 是一个功能完整、安全意识较强的内部系统。从 git 历史可见团队已进行过多轮安全加固（v0.7 P0 修复、安全加固专项），核心安全机制（认证、授权、加密、限速、安全头、XSS 防护）均已到位且实现质量较高。


最大风险点是零测试覆盖——56 张表、8500 行分析引擎、3273 行数据抓取器，全部没有自动化测试保护，任何重构或修改都存在引入回归的高风险。建议优先建立核心路径的集成测试。


最大技术债是超大文件（analytics.py 8508 行）——这会严重拖慢后续开发效率和代码审查质量，建议尽快按业务域拆分。


整体而言，项目在安全性和架构设计上表现优秀（A-），在代码质量和工程规范上有较大改进空间（C+），测试覆盖需要紧急补齐（F），运维部署配置合理（B+）。
