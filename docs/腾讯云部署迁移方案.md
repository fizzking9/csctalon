# 腾讯云部署迁移方案（客服中心管理系统）

> 版本：v1.0 · 2026-08-19
> 范围：把当前局域网 Docker Compose 部署迁移到腾讯云 CVM，面向互联网提供 **H5 响应式**访问（手机浏览器即用）。
> 已确认决策：移动端用 H5 响应式（不做微信小程序）；访问模型「公网 + HTTPS + IP 白名单」；已有已备案域名。

---

## 1. 目标与非目标

- **目标**
  - 服务部署到腾讯云，通过已备案域名 + HTTPS 稳定访问。
  - 手机端（H5 响应式）完成：**今日看板查看、运营看板查看、数据采集操作**，其余功能隐藏。
  - 数据与凭证安全（DB/Redis 不对公网暴露、凭证加密、白名单）。
- **非目标（本期）**
  - 不做微信小程序（`wechat.py`/`miniapp.py` 后端能力**保留但不上线**，作为预留）。
  - 不做 CDN / 多可用区高可用 / 自动扩缩容（当前单机足够）。

---

## 2. 资源清单（腾讯云）

| 资源 | 建议规格 | 说明 |
|---|---|---|
| CVM 云服务器 | 2C4G 起步（推荐 4C8G），系统盘 50GB + 数据盘 100GB | 数据（PG/Redis/uploads/日志）挂数据盘 |
| 系统 | Ubuntu 22.04 LTS / Debian 12 | 与本地 Docker 生态一致 |
| 域名 | 已有备案域名 | 加一条 A 记录指向 CVM 公网 IP，另加一条供 HTTPS |
| SSL 证书 | 腾讯云 SSL 免费证书（1 年，可续期） | 绑定主域名 |
| 安全组 | 见 §4 | 网络层白名单 |
| 可选 | CLB 负载均衡 | 单机可不启用，nginx 直接终止 TLS 即可 |

---

## 3. 域名与 HTTPS 配置

1. 在腾讯云 DNS 解析给主域名（如 `kf.example.com`）加 A 记录 → CVM 公网 IP。
2. 申请/下载腾讯云 SSL 免费证书（Nginx 格式：`.crt` + `.key`）。
3. 证书上传到服务器 `./certs/`，在 `web` 容器挂载并启用 443 监听（见 §5 compose 改造）。
4. 80 端口仅做 `301` 跳转到 443。

---

## 4. 网络安全加固（安全组 + 白名单）

当前 compose 已把 PG/Redis/后端只绑 `127.0.0.1`（本机内网），**迁移后保持不动**即可天然不外泄。

- **云安全组（第一道，推荐）**
  - 放行 `443`（HTTPS）、`80`（用于跳转）到 `0.0.0.0/0`；如需严格，443 也仅放行办公出口 IP 段（团队固定 IP）。
  - `22`（SSH）仅放行固定办公 IP。
  - **不开放** 5432 / 6379 / 8000。
- **nginx 应用层兜底（第二道，可选）**
  - 在 `nginx.conf` 增加 `allow <办公IP段>; deny all;`，作为安全组之外的纵深防御。
- **系统加固**
  - CVM 关闭密码登录、改用 SSH 密钥；默认端口可改为非 22。
  - 定期 `unattended-upgrades` 打系统补丁。

## 5. Docker Compose 改造要点

现有 `docker-compose.yml` 基本可复用，云上只需补三处：

### 5.1 web 服务启用 HTTPS + IP 白名单

在 `web/nginx.conf` 增加 443 server 块，并挂载证书：

- `web` 服务新增挂载：
  ```yaml
  volumes:
    - ./certs:/etc/nginx/certs:ro        # SSL 证书
  ports:
    - "80:80"
    - "443:443"
  ```
- `nginx.conf` 变更示意（关键项）：
  ```nginx
  server {
      listen 80;
      server_name kf.example.com;
      return 301 https://$host$request_uri;
  }

  server {
      listen 443 ssl;
      server_name kf.example.com;
      ssl_certificate     /etc/nginx/certs/kf.example.com.crt;
      ssl_certificate_key /etc/nginx/certs/kf.example.com.key;

      # IP 白名单（可选，若安全组已收敛可省略）
      allow 203.0.113.0/24;
      deny all;

      # ... 其余沿用现有 location（SPA 回退、/api/、/uploads/、安全响应头）
  }
  ```
- 注意：现有 `nginx.conf` 的 `server_name _;` 需改为正式域名。

### 5.2 密钥与 .env

- 从本地复制 `.env` 到服务器（**不入 git**），并**生产环境轮换**以下密钥（当前本地值不带上生产）：
  - `POSTGRES_PASSWORD`
  - `REDIS_PASSWORD`
  - `JWT_SECRET_KEY`（改后旧 token 全部失效，用户需重新登录）
  - `INIT_ADMIN_PASSWORD`（首次建账用，建账后到系统内改密）
- **注意**：`CONFIG_ENCRYPTION_KEY` 留空时，同步源加密凭证由 `JWT_SECRET_KEY` 派生。若本地已有加密的同步源凭证，**迁移时不要改 `JWT_SECRET_KEY`**，或先用旧 key 解密后重新录入；否则旧同步源密码无法解密。

### 5.3 数据目录与日志

| 目录 | 说明 |
|---|---|
| `./data/postgres` | PG 数据（见 §6 迁移） |
| `./data/redis` | Redis AOF，可重新生成（缓存无需迁移） |
| `./data/browser_states` | Playwright 登录态，建议迁移；不迁则需重新登录 BMS/SCRM |
| `./backend/uploads` | 审计贴图附件，需迁移 |
| `./logs` | nginx/backend 日志 |

## 6. 数据迁移

### 6.1 PostgreSQL（核心）

本机导出：

```bash
docker exec csctalon-db pg_dump -U csctalon -d csctalon -Fc -f /tmp/csctalon.dump
docker cp csctalon-db:/tmp/csctalon.dump ./csctalon.dump
```

服务器导入（先启动 db 容器、跑完 `alembic upgrade head` 后）：

```bash
docker cp ./csctalon.dump csctalon-db:/tmp/csctalon.dump
docker exec csctalon-db pg_restore -U csctalon -d csctalon --clean --if-exists /tmp/csctalon.dump
```

> 迁移后后端启动时会自动执行 `alembic upgrade head`（幂等），确保 schema 与代码一致（当前 head=`w1x2y3z4a5b6`）。

### 6.2 附件与登录态

```bash
rsync -avz ./backend/uploads 服务器:./backend/uploads
rsync -avz ./data/browser_states 服务器:./data/browser_states
```

### 6.3 Redis

无需迁移（纯缓存，60s TTL 自动重建）。

## 7. 部署步骤（清单）

1. 购买/配置 CVM，装 Docker + Docker Compose 插件。
2. 克隆代码，`.env` 按 §5.2 填写（轮换密钥）。
3. 上传 SSL 证书到 `./certs`，`web/nginx.conf` 加 443 + 白名单 + 正式域名。
4. `docker compose up -d --build` 启动全套。
5. 按 §6 迁移 PG/附件/登录态。
6. 配置安全组（§4）。
7. 验证：`docker compose ps` 全 healthy；HTTPS 访问正常；手机浏览器登录、今日/运营看板、数据采集都可用。
8. 备份策略：`crontab` 每日 `pg_dump` + 上传到对象存储/异地（或启用腾讯云 CDB 托管 PG 自动备份）。

---

## 8. 上线切流与回滚

- **切流**：本地与云端并行一周，团队用云端域名验证；确认无误后本地停掉定时同步（`BMS_SCHEDULE_AUTOSTART=false`）并停服，避免双写。
- **回滚**：保留本地 `./data/postgres` 最近备份；云端出问题时回切本地域名/IP，数据以本地 dump 为准。

## 9. 移动端 MVP（H5 响应式）

本期仅开放 3 项，其余路由在移动端隐藏；实现上基于现有 Vue 前端做响应式（屏幕 < 768px 走移动布局 + 移动端菜单）。

| 移动端功能 | 前端路由 | 权限 |
|---|---|---|
| 今日看板 | `/dashboards/today` | 按现有角色 |
| 运营看板 | `/dashboards/operation` | 按现有角色 |
| 数据采集（启动同步 + 进度/日志） | `/data/ingest` | 仅 admin |

- 数据采集在手机端要能**完整操作**（触发 `incremental`/`today`、查看进度条与实时日志、查看失败源），视觉按移动端精简。
- 其余（决策看板各子项、人员/分类/审计、视图构建等）在移动端菜单隐藏，后续深挖再放开。

## 10. 安全检查清单（上线前对照）

- [ ] 5432 / 6379 / 8000 未对公网开放（仅 127.0.0.1 或 VPC 内网）
- [ ] 安全组仅放行 80/443（+ 白名单），SSH 仅固定 IP
- [ ] 全站 HTTPS，80 强制跳转
- [ ] `.env` 未入库、生产密钥已轮换
- [ ] `JWT_SECRET_KEY` 轮换后的加密凭证兼容性已确认（§5.2）
- [ ] `INIT_ADMIN_PASSWORD` 已改、默认 admin 已改密
- [ ] 登录限流/失败锁定已启用（如未启用，列为上线后首批待办）
- [ ] PG 自动备份已配置并验证可恢复
- [ ] 日志轮转生效（json-file 10m×3 + ./logs 文件）
- [ ] 非 root 运行、SSH 密钥登录
