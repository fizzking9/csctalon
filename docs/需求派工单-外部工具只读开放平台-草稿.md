## 一、背景与目的

让 **workbuddy 等外部工具** 通过 `URL + Token` 从本系统**按需拉取只读数据**，自行组合生成报告/简报。

- 驱动场景：workbuddy 每半小时拉一次"当天累计接待/退款/投诉"生成简报。
- **设计取向（用户已确认）**：不做"单一大而全简报接口"，而是**开放一组带 scope 授权的细粒度只读 API**，让 workbuddy 自己组合多个端点生成报告；后续每加一类数据（绩效/人员等）= 新增一个端点 + 新增一个 scope，不破坏已有调用方。

系统已有口径经多轮审计的只读聚合（`analytics.today_kpi()` 等，缓存键 `today:kpi:*`，与 Web 看板/小程序共享）。**本需求 = 为现有只读聚合搭建一个带鉴权、带权限范围、带限频的"外部只读开放层"，不新增统计口径、不新增写路径。**

## 四、鉴权与 Token 管理（架构重点）

### 4.1 模型与表结构（用户确认：管理员生成/分发/吊销 + scope；结构已评估，见下）

- **新表 + Alembic migration**：表名建议 `external_access_tokens`。管理员**在系统内**生成 token，分发给 workbuddy 等调用方。
- token **明文只在生成时展示一次**；库中仅存 **hash**（SHA-256），校验用 `hmac.compare_digest` 常量时间比较——**严禁明文落库**。
- scope 预留可扩展集合，一期：`reception`（接待）、`refund`（退款）、`complaint`（投诉）、`brief`（一键经营简报）。后续绩效/人员 = 新增 scope 值 + 对应端点，**不动既有 token 结构**。
- **评估结论：不套 SCD Type 2**（吊销用软删 `enabled=False` 即可，无需保留 token 历史版本）；scope 用 JSONB（对齐项目 `SyncSourceConfig.options` 的 JSONB 惯例，一期仅 4 个 scope，无必要建关联表）。整体骨架复刻 `SyncSourceConfig`（`IDMixin` + `TimestampMixin` + 字段 comment 注释）。

建议表结构（Architect 可微调）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | bigint PK | `IDMixin` |
| `name` | String(64) | 调用方标识（如 `workbuddy-简报`），审计/管理界面显示 |
| `token_hash` | String(64) unique | SHA-256(token)，**不存明文** |
| `token_prefix` | String(12) | 明文前 8 位，仅管理界面识别用，不可逆推完整 token |
| `scopes` | JSONB | `["reception","refund","complaint","brief"]`，可扩展 |
| `rate_limit_per_min` | Integer nullable | 每 token 个性化限频；NULL = 用全局默认（用户要求参数化） |
| `enabled` | Boolean default True | 总开关 = 吊销（软删，即时生效） |
| `expires_at` | DateTime nullable | 可选过期时间 |
| `last_used_at` | DateTime nullable | 最后使用时间（管理界面看活跃度） |
| `created_by` / `revoked_by` | String(64) | 操作人（对齐 `SYS/system` 操作人规范） |
| `created_at` / `updated_at` | `TimestampMixin` | 时间审计 |

### 4.2 scope 校验

- 每个只读端点声明所需 scope；请求 token 不含该 scope → `403 FORBIDDEN`。
- scope 校验与端点映射表（对外 scope → 路由）由架构文档给出。

### 4.3 管理入口（用户确认：Web 管理界面，一期直接做完整页）

- 菜单位置建议：`系统设置 / 外部接入`（或复用现有"数据采集→接入"风格页面）。
- 功能：列表（名称/scope/频次/状态/最后使用时间）、生成 token（**仅显一次**弹窗）、改名、配 scope、设频次、启用/吊销、删除。
- **一期直接做完整 CRUD API + Vue 管理页**（用户确认：管理界面应很简单；骨架同项目常规列表页 + 生成弹窗，无需分期）。

## 五、只读端点（一期：接待/退款/投诉 三核心单日 + 一键经营简报[日/周/月]）

> 统一复用 `analytics.today_kpi()` 等现有只读聚合与缓存（**复用现有口径，不新写统计逻辑**）；每端点**定义独立响应 schema**（不整包透传内部大字典）。

### 5.1 维度端点（单日，`date` 缺省=今天）

> `date` 缺省 = 今天（北京时间），可传任意历史日期回看。三核心维度端点**保持单日形态**（不引入 period 参数，避免契约膨胀）。

| 端点（建议） | 所需 scope | 响应内容（一期） |
|---|---|---|
| `GET /api/v1/external/reception` | `reception` | 指定日接待量 + 昨日环比（`yoy_value/yoy_pct`）+ 服务设备数 |
| `GET /api/v1/external/refund` | `refund` | 退款笔数/金额（四路经营合计 A+B+C+D，按创建时间）+ 当日完成退款 + 真实现金流 E + 昨日环比。**金额单位：元，2 位小数** |
| `GET /api/v1/external/complaint` | `complaint` | 投诉量（service_tickets 投诉 + external_complaints + card_complaints 三表并集，落当日）+ 昨日环比 |

### 5.2 一键经营简报端点（日/周/月，本期实现）

> 用户 #4 确认：聚合便捷端点**本期实现**（原为"预留"）。供想一次拿全量 KPI 生成日报/周报/月报的场景。

| 端点（建议） | 所需 scope | 说明 |
|---|---|---|
| `GET /api/v1/external/brief` | `brief` | 一次返回接待/退款/投诉/现金流等核心 KPI，支持 `period` 时间窗口 |

- **`period` 参数（用户确认口径）**：
  - `daily`：**当日 0 点起**至当前（date 缺省今天；可配 date 回看某整天）
  - `weekly`：**按整周核算**（周一起）
  - `monthly`：**按整月核算**；若当前未满月则 **1 日至当前**
- 复用 `analytics` 的窗口解析能力（`today_kpi()` 已支持单日/start+end 周月汇总，架构层对齐 `_resolve_windows` 语义）。
- 返回建议含：`period`、`date`/`date_start`/`date_end`（北京时间）、各 KPI、`_spec` 口径注释。

> 公共参数（所有端点）：`Authorization: Bearer <token>`。
> 每个端点响应统一 `{code:0, data, message:"ok"}`；错误走 `HTTPException`（对齐 error-code.md）。
> scope 集合一期新增：`reception` / `refund` / `complaint` / `brief`（可扩展）。

## 六、频率限制（用户确认：Redis 计数 + 参数化，管理员管理，固定窗口）

- **Redis 计数**（项目已有 Redis，多调用方并发可靠）；限频作用于**外部只读端点层**。
- **参数化**：每 token 可单独配置（如每分钟 N 次，`rate_limit_per_min`）；未配则用**全局默认**；管理员可在管理界面调整。
- **窗口算法（用户确认）：固定窗口**——Redis `INCR` + `EXPIRE` 每分钟重置，实现简单、足够覆盖“每半小时拉一次”场景；后续可平滑升级滑动窗口。
- 超限响应：`429 Too Many Requests` + 业务码 `RATE_LIMITED`（**本次一次性补进 `docs/standards/error-code.md`**，用户已确认）。
- 现有登录限速是单 worker 内存滑动窗口；本需求因可能多调用方/跨 worker，**采用 Redis 固定窗口计数**（架构层给出 key 设计：token+分钟桶）。

## 七、约束

1. **框架/路径**：FastAPI。独立模块（如 `app/api/v1/external.py`）+ 独立 router（如 prefix `/external`），**不塞进** `/sync/*` 或业务模块。
2. **只读**：所有端点只读、无副作用、不触发同步/写库/缓存失效；仅查询（可命中既有 `today:kpi:*` 读缓存）。
3. **鉴权**：
   - token 库中存 **hash**（非明文）；校验 `hmac.compare_digest` 常量时间比较。
   - 吊销即时生效；被吊销 token → `401`。
   - 无任何 token（表空/功能未启用）→ 外部端点 `503`（对齐 workbuddy 模式）。
   - token 缺失/错误 → `401`；scope 不足 → `403`。
4. **Token 生成**：强随机（建议 `secrets.token_urlsafe(32)` 级别）；明文仅创建时返回一次；token **严禁进日志**。
5. **金额单位**：只读透传既有聚合，单位=**元**（`Numeric(12,2)`，2 位小数），**不加分/元换算**，响应与文档显式标注单位。
6. **时间**：遵循 `docs/数据时间字段使用规范.md`（`AT TIME ZONE 'Asia/Shanghai'`）；对外返回北京时间；`date` 缺省=今天（北京时间）。
7. **响应格式**：成功 `{code:0, data, message:"ok"}`；错误走 `HTTPException`（`{detail, code}`），对齐 `docs/standards/error-code.md`（429/RATE_LIMITED 本次一并补进）。
8. **缓存**：复用 `today_kpi()` 现有缓存键，不新增重复聚合、不穿透、不加写。
9. **日志**：项目 `logging` logger；记录调用方别名（token 名称）用于审计，**不记明文 token**。
10. **审计（用户确认：复用现有，不建独立调用审计表）**：调用记录复用现有 `operation_logs` / `system_events` 体系，不新建独立 external 调用审计表；架构层明确记录粒度与落点。
11. **文档维护（用户确认：分开维护）**：本项目“外部只读拉取”与 workbuddy “数据推送”是**两类**，文档**分开**。
    - `docs/API接口文档.md` 补一节「外部只读开放平台」（/external 模块 + 端点 + 鉴权），维持以代码为准。
    - **新建**对外的「外部只读数据接入规范」（供 workbuddy 等拉取方使用），**不并入** `workbuddy数据同步接入规范.md`（那是数据推送类）。

## 十一、测试要求（交付 Developer 时）
