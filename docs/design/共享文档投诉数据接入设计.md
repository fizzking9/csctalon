# 共享文档投诉数据接入 设计文档

> 版本: v1.0 · 2026-08-22
> 范围: 投诉登记数据(315外部投诉 / 卡商群投诉)的三态接入: 主动监测 / 被动推送 / 文件导入 + 采集方式开关

---

## 1. 背景与目标

投诉补充数据此前仅依赖 **WorkBuddy 定时推送**(被动)和 **手动文件上传**(导入)两条通道。为减少对外部工具的依赖,期望系统能像 WorkBuddy 一样**自行监测共享文档**(腾讯文档/金山文档): 填共享链接 → 微信扫码授权 → 系统按间隔自动拉取文档变化入库。

考虑开放平台注册门槛(腾讯文档个人可注册、金山文档需企业主体),**三种模式互为兜底**,均需保留,并由管理员通过**采集方式开关**选择启用哪些:

| 模式 | 交互 | 适用场景 |
|---|---|---|
| 主动监测(monitor) | 系统定时读共享文档 API | 已注册开放平台应用, 最省心 |
| 被动推送(push) | 外部工具定时推 JSON | 沿用 WorkBuddy 中转 |
| 文件导入(import) | 手动上传 xlsx/csv | 临时/一次性补数据 |

三种模式数据汇入**同一投诉台账**(`external_complaints` / `card_complaints`),共用同一套 清洗 → 指纹去重 → 按设备SN关联工单 管线,互不冲突、可并用。

---

## 2. 总体架构

```
                    ┌────────────────────────────────────────────────┐
 主动监测(腾讯文档)  │ 调度器(bms_scheduler) ── 轮询 ── tencent_doc_client ─┐
                    │     每 N 分钟检查        (OAuth+读表)            │
                    └────────────────────────────────────────────────┤
                    ┌────────────────────────────────────────────────┤
 被动推送(WorkBuddy) │ POST /sync/complaints/push (Bearer token) ─────┤
                    └────────────────────────────────────────────────┤
                    ┌────────────────────────────────────────────────┤
 文件导入(手动)      │ 前端 Upload.vue → /uploads 解析 → Diff → 入库 ──┤
                    └────────────────────────────────────────────────┤
                                            │
                                            ▼
                    complaint_sync: 清洗/指纹去重/SN关联工单(统一管线)
                                            │
                                            ▼
                            external_complaints / card_complaints
                                    (decision看板·投诉专项展示)
```

- 三模式入口统一在「数据采集 → 投诉接入」(Web), 内部三个 tab 切换, 顶部为采集方式开关。
- 采集方式开关(`ingest_mode_configs`)决定 monitor/push 是否真正生效:
  - monitor 关闭 → 调度器停止轮询;
  - push 关闭 → push 接口返回 503(即使 token 已配置);
  - import 手动操作, 恒可用。

## 3. 主动监测(腾讯文档)设计

### 3.1 OAuth2.0 授权流程

腾讯文档开放平台采用 OAuth2.0 授权码方式(与 WorkBuddy「点击授权」一致, 但应用凭证由我方注册):

```
管理员填 ClientID/Secret ──► 系统生成授权链接 ──► 用户微信/QQ扫码同意
      ──► 腾讯回跳 {BASE}/api/v1/sync/docs/tencent/callback?code=xxx
      ──► 系统用 code 换 access_token + refresh_token(Fernet加密落库)
      ──► 后续调用 OpenAPI 均带 access_token
```

- access_token 有效期 30 天, refresh_token 1 年; 过期自动用 refresh_token 刷新, 失效需重新授权。
- 回调地址默认按请求地址推导, 也可在 UI 显式配置(需与开放平台后台登记的回调域名一致, 生产建议 HTTPS)。

### 3.2 关键 OpenAPI

| 用途 | 接口 |
|---|---|
| 授权链接 | `GET https://docs.qq.com/oauth/v2/authorize` |
| 换 token | `GET https://docs.qq.com/oauth/v2/token` (grant_type=authorization_code) |
| 刷新 token | `GET https://docs.qq.com/oauth/v2/token` (grant_type=refresh_token) |
| encodedID→fileID | `GET {OPENAPI}/drive/v2/util/converter?type=encoded_id&value=...` |
| 查询子表 | `GET {OPENAPI}/sheetbook/v2/{fileID}/sheets-info` |
| 读取区域 | `GET {OPENAPI}/spreadsheet/v3/files/{fileID}/{sheetId}/{range}` |
| 文档元信息 | `GET {OPENAPI}/drive/v2/files/{fileID}/metadata` |

读取限制: 单次 ≤1000 行 / ≤200 列 / ≤10000 格; 客户端按 900 行/块分页拉取, 按实际数据宽度裁剪列。

### 3.3 同步时序

```
调度器每 60s 检查 should_sync_tencent_doc():
  enabled && 凭证齐全 && 已授权 && 链接已配 && monitor 开关开 && 距上次≥interval(默认20min)
    └─► asyncio.to_thread(sync_tencent_doc_safe)
          └─► 确保 token 有效(过期则刷新)
          └─► 解析链接 → fileID(缓存, 链接变化时失效)
          └─► 查子表 → 按名取 315/卡商 两 Sheet(未配置取首表)
          └─► 分页读表 → 表头映射为 [{列名:值}]
          └─► 组装 payload → sync_complaints_from_payload(复用统一管线)
          └─► 更新 doc_sync_configs.last_sync_* (状态/统计/错误)
```

## 4. 统一数据管线(complaint_sync)

三种模式最终都进入 `sync_complaints_from_payload`(sync_source 区分: `workbuddy` / `tencent_doc` / 手动导入):

1. **列名映射**: 兼容中文列名与英文字段名(COLUMN_TEMPLATES)。
2. **数据清洗**: SN 去括号备注/多SN取首、日期按北京时间解释、姓名/金额防御性校验、长度截断。
3. **指纹去重**: `md5(投诉日期|手机号|SN|归一化问题)` 作为 dedup_hash upsert, **重复推送/多源重复不会累积**(重复行仅更新)。
4. **SN 关联工单**: 按 device_sn 匹配外部投诉类工单写回 `matched_ticket_no`。
5. **同步日志**: 每次写入 `complaint_sync_logs`(source_file/sync_source/行数/新增/更新/失败/关联数)。

## 5. 采集方式开关

表 `ingest_mode_configs`, 每行一个模式, seed 三行默认开启。

| mode | name | 关闭后的效果 |
|---|---|---|
| monitor | 主动监测 | `should_sync_tencent_doc` 返回 False, 调度器停止轮询 |
| push | 被动推送 | `POST /sync/complaints/push` 返回 503 |
| import | 文件导入 | 恒可用(UI 置灰, 无开关语义) |

前端「投诉接入」页顶部开关卡片: 关闭某模式 → 对应 tab 置灰; monitor+push 同时开启 → 黄色提示(去重兜底不会脏数据, 建议二选一避免冗余采集/日志混淆)。

## 6. 数据库变更

### doc_sync_configs(每平台一行, token Fernet 加密)

| 列 | 说明 |
|---|---|
| platform | tencent / wps(预留) |
| app_id / app_secret | 开放平台应用凭证(加密) |
| redirect_uri | OAuth 回调地址 |
| access_token / refresh_token / open_id / token_expires_at | 用户授权 token(加密) |
| doc_url / file_id | 共享表格链接 / 解析出的 fileID(缓存) |
| external_sheet_name / card_sheet_name | 315 / 卡商 Sheet 名(留空取首表) |
| enabled / sync_interval_minutes | 平台开关 / 轮询间隔 |
| last_sync_at / last_sync_status / last_sync_summary / last_error | 最近同步状态 |

### ingest_mode_configs

| 列 | 说明 |
|---|---|
| mode | monitor / push / import |
| name | 显示名 |
| enabled | 是否开启 |

迁移: `d5f6a7b8c9d0_add_doc_sync_configs` → `e1f2a3b4c5d6_add_ingest_mode_configs`(单 head 链)。

## 8. 前端

- `data/TencentDocSync.vue`: 主动监测配置/授权/状态/手动同步/最近同步。
- `data/WorkBuddyPush.vue`: 推送接口信息/token 状态/推送日志。

## 9. 风险与后续

- 金山文档(wps)接入: 模型已预留 platform 字段, 需补一个 wps 读取适配(开放平台需企业主体, 等待资质就绪)。
- 腾讯文档 OpenAPI 响应结构随版本可能有差异: 客户端已做多形态防御解析, 解析失败给出可读错误并记录到配置行。
- 读取限制: 超大表格(>1万格/次)已分页; 若单表超 5 万行建议增量策略(当前全量+指纹去重已够用)。
