# CSCTalon 前端界面组织规范

> 适用技术栈: Vue 3 + Vite + Element Plus + ECharts + Pinia。目标是"不培训就会用、新页面照模板拼装"。

## 1. 页面分层(内容组织四层)

任何页面按此四层组织,禁止跳层:

1. **页头**: 页面标题(左) + 一句话副标题说明用途 + 主操作按钮(右, 右上角)。
2. **筛选区**: 顶部卡片内放 FilterBar/筛选控件(状态/日期/关键词), 变更即刷新。
3. **主体区**: 表格(列表页) 或 卡片栅格(看板页); 看板优先复用 dashboard 组件(KpiCard/ChartCard/SectionHeader)。
4. **页脚区**: 分页 + 总数统计(列表页); 看板页可不设。

## 2. 四大交互范式(页面模板)

| 范式 | 结构 | 适用 |
|------|------|------|
| 列表页 | 页头 + 筛选 + 表格 + 分页 + 导出 + 右上主按钮 | 异常/标签/发票/政策/排班/知识库 |
| 详情页 | 面包屑 + 元信息头(el-descriptions) + 主体 + 侧栏/底部时间线 | 异常详情/投诉审计/报告详情 |
| 表单页 | 必填 ≤3 项置顶 + 其余折叠"更多" + 保存草稿/提交 | 所有登记 |
| 导入页 | 模板下载 + 上传 + 预览复核 + 确认(回执成功/失败) | 标签批量/排班/发票 |

## 3. 菜单与导航组织(侧边栏)

- 一级菜单按角色可见性分层: 全员可见(运营看板/工作台/我的待办/数据中心/发票/知识库) → 管理层(决策看板/管理闭环) → 管理员(系统管理)。
- 同一业务域的页面放同一子菜单(如 管理闭环: 报告/周报/措施/异常/排班/预警/跨部门), 不散落。
- 菜单名与页面 title 一致; 命名避免歧义(如"设备专项标签"区别于"专项任务")。
- 隐藏路由(hidden: true)用于详情页/跳转页, 不进菜单。

## 4. 全局状态色板(统一语义)

| 状态族 | 颜色 | 语义 |
|--------|------|------|
| 待处理/待审/待回看 | warning(黄) | 需要动作 |
| 进行中/执行中 | primary(蓝) | 已启动 |
| 已完成/生效/闭环 | success(绿) | 结束 |
| 异常/失效/超期 | danger(红) | 需关注 |
| 归档/废止 | info(灰) | 只读留存 |

统一封装在 `web/src/utils/statusColor.js`(已存在), 页面禁止私写配色。

## 5. 组件复用(禁止重复造轮子)

- KPI 卡 → `KpiCard`; 图表卡 → `ChartCard` + `BaseChart`; 区块标题 → `SectionHeader`; 筛选条 → `FilterBar`; 三列队列 → `QueuePanel`。
- 新页面先引入公共组件拼装, 禁止内联 KPI 卡/图表卡样式。
- 需要新 props 时向后兼容扩展公共组件, 不在使用页私写覆盖类名。

## 6. 角色化工作台(第一屏差异化)

| 角色 | 第一屏 |
|------|--------|
| 系统管理员 | 全局 KPI + 系统告警 + 待审队列 |
| 主管 | 全局 KPI + 例外清单(异常/超期/待回看) + 待审 |
| 专项组长 | 本专项 KPI + 本专项待办 + 本组排班 |
| 专员 | 本人待办 + 本人数据 + 被指派专项 |
| 普通客服 | 待读政策 + 本人接待 + 提交发票入口 |

## 7. 审核清单(梳理界面时逐项过)

- [ ] 每个页面是否四层结构完整?
- [ ] 是否落在四大范式之一?
- [ ] 菜单是否按角色分层、业务归组、命名无歧义?
- [ ] 状态色是否用统一色板?
- [ ] 是否复用了公共组件而非内联样式?
- [ ] 必填项是否 ≤3、其余折叠?
- [ ] 空数据是否有 el-empty 提示?
- [ ] 加载是否有 v-loading?
