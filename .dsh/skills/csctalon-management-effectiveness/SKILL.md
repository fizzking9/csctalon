# CSCTalon 管理效果/管理闭环设计规范

> 定位: 系统是解决问题的, 不是制造麻烦的。管理层体验 = 看结果不翻过程、管例外不管全量、催闭环不催人。

## 1. 例外管理(主管视角核心)

- 主管首页只突出「需要动作」的项: 异常/超期/待回看/待审/积压, 正常数据折叠不打扰。
- 看板默认口径: 红色=要处理, 黄色=快到期, 绿色=正常不显示。
- 每个「例外」可一键跳转到处理页(详情/跟进/审核), 不要求主管跨页面拼信息。

## 2. 归因不归责(数据真实的地基)

- 投诉审计/退款挽回/绩效数据**只做分析汇总, 不做扣分依据**。
- 审计结论用于改进流程, 不挂钩个人绩效扣罚。
- 系统内任何"审计/评估"文案都强调改进导向, 避免逼人"优化数据"。

## 3. 管理成本核算(砍掉没人看的报表)

- 每张报表/看板必须回答: **谁看? 看完做什么决策?** 答不上就不上线。
- 管理动作(登记/审计/跟进/报表)字段能简则简, 抓核心。
- 已有报表定期审计: 使用频率低的合并/下线, 不累积僵尸页面。

## 4. 周报/复盘自动化

- 周报 10 项框架数据自动填充(接待/退款/投诉/措施/异常), 人只补结论。
- 周例会只审到期措施 + 例外项, 不每周重复全量审。
- 周报确认后固化快照, 可持续批注(活文档), 不下钻不强制派生报告。

## 5. 预警驱动(让异常自己浮现)

- 预警规则可配置(退款激增/工单积压/异常激增/投诉激增), 调度器定时扫描。
- 预警进待办中心 + 通知中心, 人从"盯数据"变"确认预警"。
- 预警幂等(同日同规则只一条), 避免刷屏。

## 6. 绩效只汇总不扣分

- 绩效看板呈现工作量/效率/成功率**汇总与趋势**(纵向比进步), 不排名惩罚。
- 人效算法口径(专项难度系数/本职转接)文档化, 数据变化可追溯解释。
- 不把投诉/异常数据直接折算进个人扣分。

## 7. 管理效果评审清单(梳理管理层体验时逐项过)

- [ ] 主管第一屏是否只突出例外(异常/超期/待审)?
- [ ] 是否每个例外一键可达处理页?
- [ ] 报表是否都能回答"谁看/看完做什么决策"?
- [ ] 是否有没人看的僵尸报表可下线?
- [ ] 周报是否自动填充、只补结论?
- [ ] 预警是否驱动处理而非人工盯数据?
- [ ] 绩效是否只汇总不扣分、口径可追溯?
- [ ] 管理动作字段是否最简?
